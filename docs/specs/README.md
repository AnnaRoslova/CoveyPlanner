# Спецификации CoveyPlanner

С октября 2026 года работаем по **spec-driven development**: сначала спецификация, потом код.

## Что такое спецификация у нас

Спецификация (спека) — markdown-файл в этой папке, который описывает одну фичу или одну часть модели
так, чтобы по нему можно было написать код и тесты, не задавая вопросов. В ней:

- **цель** — зачем это нужно, какую боль закрывает;
- **термины** — что значат слова (дело, шаг, проект, занятие, скрепка…), один смысл у каждого;
- **правила** — пронумерованные, проверяемые («если … то …»), на них ссылаются тесты и коммиты (`TSD-12`);
- **модель данных и миграция** — что меняется в таблицах, как переносятся существующие данные;
- **интерфейс по экранам** — что видно и что происходит по клику/перетаскиванию;
- **крайние случаи** — разобраны явно, с ответом;
- **что НЕ делаем** — чтобы не расползалось;
- **критерии готовности** и **список e2e-сценариев**;
- **открытые вопросы** — то, что решает Анна. Пока вопрос открыт, в спеке стоит предложенный ответ с пометкой «(предложение)».

Спеки «как есть» (`model-principles.md`, `habits.md`) описывают уже работающее поведение — по коду, а не по памяти.
CLAUDE.md остаётся общим ТЗ и правилами проекта; спеки — подробное и точное описание отдельных частей.
Если CLAUDE.md и спека расходятся, правильной считается утверждённая спека, а CLAUDE.md правится в том же коммите, что и код.

## Порядок работы

1. **Спека.** Claude пишет или правит спеку (и при необходимости HTML-макет рядом), коммитит только `docs/specs/`.
2. **«Ок» Анны.** Анна читает, отвечает на открытые вопросы, правит или говорит «ок». Статус в шапке спеки: `черновик` → `утверждена`.
3. **План.** К утверждённой спеке — `*.plan.md`: этапы, каждый — зелёные `dotnet build` / `dotnet test`, отдельный коммит.
4. **Код.** По плану, этап за этапом; в сообщении коммита — номера правил спеки. В конце — e2e-сценарии из спеки и правка CLAUDE.md.
5. **«Передумали».** Любое изменение поведения — сначала правка спеки (и «ок»), потом код. Код, который расходится со спекой, — баг либо кода, либо спеки; молча не чиним ни то, ни другое.

Проверки на данных — только на **копии** базы (`%LOCALAPPDATA%\CoveyPlanner\planner.db` → папка для временных файлов).
Рабочий сервер (`:5070`) при подготовке спек не трогаем, даже GET-запросами.
