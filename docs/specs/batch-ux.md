## 1. Проекты понятнее (BP)

**Сейчас.** Вход в проекты — 🛠 в шапке недели; первый «+ шаг» в окне мысли молча делает её проектом (S, N6.4) — мысль уходит из ленты.

**Правила**
- **BP1. Вкладки правой колонки.** Над правой колонкой — переключатель **«Мысли · 46 | Проекты · 3»** (сегменты, выбранный залит, D-система).
  Число — сколько открытых мыслей ленты / открытых проектов. Значок 🛠 в шапке убирается (ui-declutter, U3-a). Выбор запоминается в браузере
  (как сейчас режим панели, N6.8). Свёрнутая правая колонка — на полоске два значка-вкладки.
- **BP2. Мысль → проект только явно.** В окне мысли **нет «+ шаг»** и блока «Шаги». Есть кнопка **«🛠 Сделать проектом»** с подписью под ней
  «добавить шаги и раскладывать их по дням». Нажали — мысль становится проектом (`IsProject`), окно закрывается, плашка
  **«Теперь в «Проектах» · Показать · Вернуть»**: «Показать» — вкладка «Проекты», проект подсвечен и раскрыт со строкой «+ шаг»;
  «Вернуть» — снова мысль на своём месте в ленте.
- **BP3. Дело в дне** (не мысль): «+ шаг» в «Подробнее» остаётся и делает проектом, как сейчас (S/N6.3) (предложение — вопрос BP-a);
  «🛠 сделать проектом» — в «⋯» (ui-declutter, U2.A).
- **BP4. Пустая вкладка «Проекты»** — текст: «Проект — дело из нескольких шагов, например «Ремонт» или книга. Шаги можно раскладывать по дням.»
  и кнопка «+ проект» (добавить, D2).
- **BP5. Автоотметка проекта** (все шаги выполнены, S12): плашка **«„Ремонт“ выполнен → в «Выполненном» · Показать · Вернуть»**
  (слово «выполнен» — по словарю, BG; Анна писала «завершён» — вопрос BG-a). «Показать» — «📈 Итоги · Выполненное», проект подсвечен.
  «Вернуть» — снять отметку проекта и шага, который её вызвал (как «вернуть» сейчас).
- **BP6. 🛠 у проекта везде:** строка проекта в дне (есть), «↳ 🛠 Ремонт» у шага (в строке и в окне), варианты поля «Проект» («🛠 Ремонт»),
  вкладка «Проекты», «Выполненное», поиск (BK), недельный обзор.

**Крайние случаи.** Мысль с шагами из прошлого (до BP2) — уже проект, она в «Проектах»; менять нечего. «Вернуть» после «Сделать проектом» —
мысль без шагов, `IsProject = false`. Поиск ленты, совпавший с проектом, — «🛠 в проектах: N» (как сейчас) ведёт на вкладку «Проекты».

**Модель.** Нет. **API.** Без изменений (`PUT /api/tasks/{id}/project`).
**e2e** (`projects.mjs`, `feed-done.mjs`, новый `project-tabs.mjs`): вкладки и числа; в окне мысли нет «+ шаг»; «Сделать проектом» → плашка → «Показать»;
пустая вкладка — текст и «+ проект»; автоотметка — плашка «выполнен → в «Выполненном»».
**Не делаем.** Вложенные проекты, шаблоны проектов, сроки.

## 2. Словарь и «Как это устроено» (BG)

**BG1. Словарь** — одни и те же слова во всём интерфейсе (подписи, плашки, подсказки, окна, e2e-тексты):

| Слово | Одной фразой | Не путать |
|---|---|---|
| **мысль** | запись в ленте «Когда-нибудь», без даты | не «дело ленты», не «задача» |
| **дело** | то, что делают в конкретный день или на этой неделе | мысль, поставленная в день, — уже дело (та же запись) |
| **проект** | дело из нескольких шагов («Ремонт», книга), живёт во вкладке «Проекты» | не категория |
| **шаг** | часть проекта; его можно поставить в день | у шага нет своих шагов |
| **цель** | «большой камень» роли на неделю: что сделать N раз | не дело |
| **камень** | то же, что цель недели (слово Кови); на записях — значок ◆ «занятие цели» | **не** само дело |
| **занятие** | дело, которое засчитывается в цель | |
| **привычка** | цель «каждую неделю» с «🫙 копить» | не отдельная вещь |
| **скрепка** | одно выполненное занятие привычки; копятся в **банку** | |
| роль, измерение пилы, категория, неразобранное, на неделе, корзина, выполненное | — как в CLAUDE.md | |

**BG2. Расхождения, найденные в интерфейсе, — что поправить**

| Где | Сейчас | Стало |
|---|---|---|
| пилюля на записи дня, окно занятия | «камень» (так названо **дело**) | ◆ + подсказка «занятие цели «Бег»»; в окне — «◆ занятие цели «Бег» · 1 из 3» |
| окно цели | пилюля «цель» | «цель недели» |
| окна цели и занятия | «сделано 1 из 3» | «выполнено 1 из 3» |
| плашка автоотметки | «Все шаги сделаны — «…» выполнено» | «„…“ выполнен → в «Выполненном»» (BP5) |
| экран и подписи «Копилки», «Копилки привычек» (12 мест) | «Копилки» | «Привычки» (вкладка «📈 Итоги · Привычки»); «банка» — остаётся частью привычки |
| окно мысли | поле «Подробно» | «Заметки» (как у дела и цели) |
| плашки удаления (8 мест) | «Удалено «…»» | «„…“ в корзине · Вернуть» (удалено ещё не навсегда) (предложение) |
| окно мысли | плейсхолдер «Что сделать» | «Мысль» ⚠ |
| отчёт | «что сделано за период» | «что выполнено за период» |

Найти остальные — `grep` по `Components`, `Services` на варианты из таблицы; правка в одном коммите с e2e.

**BG3. «Как это устроено»** — экран поверх недели (как «Итоги»), открывается клавишей **?** и ссылкой в «⚙ Настройки»:
- словарь BG1 — каждое понятие одной фразой;
- **схема** (SVG, цвета темы): мысль → (в день) дело → ✓ выполненное; мысль → 🛠 проект → шаги → дни; цель недели → занятия ◆ → ✓;
  цель «каждую неделю» + 🫙 → привычка → скрепки → банка; роль → цели; миссия → строки ролей;
- пояснения, убранные из интерфейса (D5): «большие камни этой недели», «шаблон занятий: новые занятия берут эти значения»,
  «изменения постоянной цели — с этой недели и дальше», «одно занятие цели в день», «стартовое число» и др.;
- таблица горячих клавиш (BK).

**Модель.** Нет. **e2e** (`glossary.mjs`): «?» открывает экран, Esc закрывает; на экранах нет слов «Копилки», «сделано», «Подробно»; ◆ с подсказкой.

## 4. Дашборд во вкладке «Отчёт» (BD)

- **BD1.** Переключатель **«Список ⇄ Дашборд»** (запоминается). Период — общий с отчётом (неделя / месяц / N месяцев / год / свой, поле U3).
- **BD2. Привычки — тепловая карта по дням:** столбцы — недели периода, строки — Пн…Вс, ячейка — скрепок в этот день (0 — пусто, 1, 2, 3+ —
  три насыщенности `--b` в теме). Выбор «все привычки ▾» / одна. Каникулы — ячейки со штриховкой. Справа: **всего скрепок** за период,
  **текущая серия** 🔥 (недель, как на карточке) и **лучшая серия** (самая длинная за всю историю). Подсказка ячейки: «Чт 22 окт · Бег, 10к шагов».
- **BD3. «Колесо» пилы:** сколько **выполненных занятий** пришлось на Тело / Ум / Дух / Общение за период (занятие считается в измерении,
  если у его цели эта роль; несколько ролей — в каждой). Рисунок — 4 сектора-лепестка от центра (длина — доля от максимума), цвет — цвет роли,
  подписи и числа. Пустое измерение — серый лепесток «0».
- **BD4. Баланс ролей:** выполненные дела за период (по дню отметки, как V) по ролям — горизонтальные полосы цвета роли, число справа;
  дела с несколькими ролями — в каждой; «без роли» — внизу. Измерения пилы — отдельной группой сверху (предложение).
- **BD5. Доля II квадранта по неделям:** столбик на неделю — % выполненных дел недели с квадрантом II **среди дел с отмеченным квадрантом**;
  под столбиком мелко «из 7»; подсказка «без квадранта: 12» (предложение — вопрос BD-a). Цель Кови — II побольше: столбики мятные, без «оценок».
- **BD6. «Давно лежат»:** сколько мыслей старше срока (BS) и топ-5 самых старых: «Сад на балконе · 8 мес»; клик — окно мысли.
- **BD7. Графики — свои:** SVG и CSS в Razor-компонентах, без библиотек и CDN; цвета — переменные темы и цвета ролей; у каждого блока
  есть текстовая версия (`<title>`, таблица для диктора); контраст подписей — как основной текст (themes-contrast).
- **BD8. API:** `GET /api/dashboard?from=&to=` — одним ответом: скрепки по дням и привычкам, серии (текущая, лучшая), занятия по измерениям,
  выполненное по ролям, II-квадрант по неделям, давно лежащие мысли. Лучшая серия — `HabitStatsCalculator` (новое поле `BestWeekStreak`,
  unit-тесты: пауза не рвёт, второй пропуск рвёт, каникулы замораживают).

**e2e** (`dashboard.mjs`): переключатель; на демо-данных — ячейки с числами, 4 лепестка, полосы ролей, столбики недель, «давно лежат».
**Не делаем.** Экспорт картинок, сравнение периодов, цели по числам.

## 5. Старые мысли (BS)

- **BS1. Возраст мысли** — от **последнего изменения** мысли. Поля сейчас **нет** (у дела только `CreatedAt`, `CompletedAt`, `TrashedAt`) — добавляем
  `Tasks.UpdatedAt` (миграция; у существующих — `CreatedAt`). Меняют `UpdatedAt`: название, заметки, категория, шаги/проект, возврат в ленту,
  снятие отметки; **не** меняют: порядок перетаскиванием внутри категории, раскрытие категории (предложение — вопрос BS-a).
- **BS2. Срок** — по умолчанию **3 месяца**; в «⚙ Настройки»: 1 / 3 / 6 / 12 мес или «своё» (1–36 мес). Хранится на сервере (`AppSettings.StaleMonths`).
- **BS3. Метка возраста** у мысли в ленте — только у мыслей **старше срока**: справа «8 мес» цветом `--a-ink` (12px). Точный возраст —
  в подсказке строки при наведении **у всех** мыслей («лежит 2 мес · с 14 авг») (BS-b). Не у проектов (они во вкладке «Проекты») ⚠.
- **BS4. Плашка о перешагнувших срок** — при загрузке приложения (и в полночь, вместе с «Сегодня»): одна мысль —
  «„Сад на балконе“ лежит уже 3 мес · Посмотреть · Оставить»; несколько — «5 мыслей лежат больше 3 мес · Посмотреть».
  «Посмотреть» — лента в режиме «давно лежат» (список старых мыслей, как поиск; крестик — выйти); «Оставить» — `Tasks.KeptAt = сейчас`:
  мысль снова «свежая» на один срок (метка и подсказка возраста — по-прежнему от `UpdatedAt`).
  О каждой мысли напоминают **один раз за перешагивание**: `Tasks.StaleNotifiedAt` — когда показали плашку; снова — только если мысль
  перешагнула срок позже этого (после «Оставить» или правки).
- **BS4a. Установка.** Возраст — честно (у существующих — от даты создания). Мыслям, **уже** старым в момент установки, миграция ставит
  `StaleNotifiedAt` = момент миграции: плашек о них нет, они только в «Давно лежат» (дашборд, режим ленты) и в недельном обзоре.
  Плашки — только для перешагнувших срок после установки. Число таких мыслей на копии — в metrics.md.
- **BS5. Кто «старый»:** мысль (в ленте, не проект, не выполнена, не в корзине), у которой `max(UpdatedAt, KeptAt) + срок ≤ сегодня`.

**Модель/миграция** `StaleThoughts`: `Tasks.UpdatedAt` (DateTime, не null, = `CreatedAt`), `Tasks.KeptAt` (DateTime?), `Tasks.StaleNotifiedAt` (DateTime?, BS4a), таблица `AppSettings`
(одна строка: `StaleMonths` = 3; потом — `Mission`, `ShowMissionInPanel`, BM). Сначала — на копии: сверка числа дел, мыслей, корзины, скрепок;
отчёт: сколько мыслей сразу окажутся «старыми» (у старых записей `UpdatedAt` = дата создания).
**API:** `GET/PUT /api/settings`, `POST /api/tasks/{id}/keep`; `UpdatedAt`, `KeptAt` — в `TaskDto`.
**e2e** (`stale.mjs`, часы сервера подменяются в тесте): метка «4 мес»; плашка одной и нескольких; «Оставить» — не напоминает; срок из ⚙.
**Не делаем.** Автоудаление, архив старых мыслей, письма/уведомления ОС.

## 6. Горячие клавиши (BK)

| Клавиша | Действие |
|---|---|
| **N** | записать мысль: фокус в «Записать мысль…» (правая колонка — на вкладку «Мысли», если свёрнута — раскрыть) |
| **D** | дело на сегодня: перейти к текущей неделе, в сегодняшнем дне открыть «+ дело» |
| **← / →** | прошлая / следующая неделя |
| **T** | к сегодня |
| **Ctrl+K** или **/** | быстрый поиск по всему (BK2) |
| **H** | «📈 Итоги» |
| **?** | «Как это устроено» |
| **Ctrl+Enter** | сохранить окно (есть) |
| **Esc** | закрыть меню, окно, экран (есть) |
| *предлагаю:* **P** | вкладки «Мысли ⇄ Проекты» |
| *предлагаю:* **W** | недельный обзор |
| *предлагаю:* **Ctrl+Z** | «Вернуть» на последней плашке (пока она видна) |

- **BK1.** Клавиши без Ctrl **не срабатывают** при наборе текста (фокус в `input`, `textarea`, `[contenteditable]`) и когда открыто окно (кроме Esc,
  Ctrl+Enter, Ctrl+K); с Alt/Meta — не перехватываются. Одна точка обработки — `js/hotkeys.js` + сервис `Hotkeys` (C#).
- **BK2. Быстрый поиск:** окно по центру сверху, поле и список результатов по группам «Дела · Мысли · Проекты · Цели» (до 8 в группе, по совпадению
  в названии и заметках; дела — с датой «Чт 22 окт», выполненные — зачёркнуто, корзина — не ищется). ↑↓ — выбор, Enter — открыть:
  дело — перейти на его неделю и открыть окно; мысль — вкладка «Мысли», окно; проект — вкладка «Проекты», окно; цель — её неделя и окно цели.
  API `GET /api/search?q=` (сервер ищет по всем неделям).
- **BK3.** Подсказка клавиши — в `title` кнопок («Итоги (H)»), полный список — в «Как это устроено».

**e2e** (`hotkeys.mjs`): каждая клавиша; набор «n» в поле не открывает ничего; поиск находит дело другой недели и открывает его.
**Не делаем.** Настройку клавиш, «vim-навигацию» по строкам.

## 7. Нет связи с сервером (BN)

**Сейчас.** Запрос не прошёл (`HttpRequestException`) → «Нет связи с сервером.» на 6 с, экран перечитывается — **правка пропадает** (оптимистичное
изменение откатывается, если перечитать удалось; если нет — экран и сервер расходятся).

- **BN1. Очередь изменений.** Не прошедшее из-за связи (не ответ сервера 4xx/5xx) изменение **остаётся на экране** и встаёт в очередь
  (в памяти, по порядку). Следующие изменения — тоже в очередь, за ним (порядок сохраняется).
- **BN2. Плашка** — заметная (цвет `--warn`), **не исчезает сама**, вверху (D7): «Нет связи — изменения не сохранены (3), повторю попытку · Повторить сейчас».
- **BN3. Повтор:** через 2, 5, 10, 30 с, дальше — каждые 30 с; сразу — при событии `online` и когда окно снова активно. Получилось — очередь уходит
  по порядку; плашка «Связь восстановлена — сохранено 3» на 4 с; экран перечитывается.
- **BN4. Ответ сервера с ошибкой** при отправке очереди (например, дело удалили с другого устройства) — как сейчас: сообщение сервера, экран
  перечитывается; остальная очередь отправляется дальше.
- **BN5. Закрыть вкладку при непустой очереди** — браузер спрашивает «Изменения не сохранены» (`beforeunload`).
  Очередь между перезагрузками **не хранится** (предложение — вопрос BN-a: хранение в браузере сложнее из-за временных Id новых записей).
- **BN6. Отложенное удаление** (6 с) — тоже через очередь. Пока очередь не пуста, перечитывание с сервера не затирает экран.

**e2e** (`offline.mjs`, сервер останавливается в тесте или запросы перехватываются Puppeteer): правка без связи остаётся, плашка с числом;
связь вернулась — сохранено, плашка «Связь восстановлена»; порядок двух правок сохранён; закрытие вкладки — вопрос.
**Не делаем.** Полный офлайн-режим PWA с синхронизацией и разрешением конфликтов.

## 8. Недельный обзор (BR)

- **BR1. Вход:** кнопка «🗓 Недельный обзор» в шапке «📈 Итоги», клавиша **W** (BK). **Напоминание:** в воскресенье, при первом открытии
  приложения после 12:00 — плашка «Неделя заканчивается · Недельный обзор» (раз в неделю, дата в браузере); пропустили — в понедельник
  до 12:00 ещё раз (предложение — вопрос BR-a).
- **BR2. Экран** поверх недели: шаги **1–5** точками сверху, «Назад» / «Дальше», Esc — выйти (сделанное в шагах уже сохранено).
  Обзор — по **текущей** неделе (в понедельник до 12:00 — по прошлой).
- **BR3. Шаг 1 «Что не сделано»:** невыполненные дела недели (в днях и «на неделе»), группами по дням; у каждого — 4 кнопки-сегмента:
  **«на след. неделю»** (как в меню даты: без дня под ролью; без роли — подменю ролей, B3) / **«в ленту»** / **«в корзину»** / **«оставить»**
  (ничего). Занятия целей — отдельным блоком «Камни»: у разовой цели — «на след. неделю» (занятие переходит к той же цели на той неделе, как
  перенос сейчас) / «оставить» / «в корзину»; у постоянной цели — только «оставить» / «в корзину» (на следующей неделе цель и так будет).
  Наверху — «Отложить всё на след. неделю» (кроме занятий постоянных целей) (предложение).
- **BR4. Шаг 2 «Привычки»:** по каждой привычке — скрепок за неделю / норма, точки дней, 🔥 серия; ⚠ пауза — «не пропускай дважды».
- **BR5. Шаг 3 «Давно лежат»:** мысли старше срока (BS) — «Оставить» / «в корзину» / «на след. неделю» / «открыть».
- **BR6. Шаг 4 «Миссия и роли»:** текст миссии и строка «кем я хочу быть» каждой роли (BM), только чтение, ссылка «изменить».
- **BR7. Шаг 5 «Камни на следующую неделю»:** по ролям — цели следующей недели (постоянные уже там), «+ цель» на месте;
  у роли без целей — подсказка «у роли «Дом» нет камней». «Готово» — перейти на следующую неделю.
- **BR8.** Ничего нового не хранится: шаги — это обычные действия (перенос, корзина, «+ цель») с их плашками и «Вернуть».

**e2e** (`weekly-review.mjs`): шаги и «Назад/Дальше»; каждое действие шага 1 (в т. ч. занятие разовой цели); «у роли … нет камней»; «+ цель»
создаёт цель следующей недели; напоминание в воскресенье (часы подменяются).
**Не делаем.** Оценки недели, дневник, статистику обзоров.

## 9. Миссия (BM)

- **BM1. «Моя миссия»** — экран поверх недели: свободный текст (до 5000 знаков, перенос строк сохраняется) и под ним — роли по порядку,
  у каждой одна строка **«кем я хочу быть в этой роли»** (до 200 знаков). Сохраняется по уходу из поля (без кнопки «Сохранить»), плашки нет.
- **BM2. Где видна:** при наведении на название роли — всплывающая подсказка с её строкой (вместе с подсказкой сворачивания U1);
  в окне роли — то же поле; в недельном обзоре (BR6); по желанию — **свёрнутым блоком вверху левой панели** «✦ Моя миссия ▸»
  (раскрывается текстом миссии, запоминается; включается в «⚙ Настройки», по умолчанию выключено (предложение)).
- **BM3. Вход:** «⚙ Настройки» → «Моя миссия», блок в левой панели, шаг 4 обзора.
- **BM4.** Пустая миссия — подсказка «Начни с конца: кем ты хочешь быть?» (BM-a).
- **BM5. Без цитат.** В текстах интерфейса нет упоминаний Кови и «7 навыков» (вдохновляемся, не цитируем; товарные знаки) — убрать везде
  (например, «Кови советует 1–3 больших камня» → «лучше 1–3 больших камня»); в документации и коде — можно.

**Модель/миграция** `Mission`: `AppSettings.Mission` (text?), `AppSettings.ShowMissionInPanel` (bool), `Roles.Vision` (string?, ≤ 200).
API: `GET/PUT /api/settings` (миссия — часть настроек), `PUT /api/roles/{id}` с `Vision`. Сверка на копии: роли, их порядок и цвета не меняются.
**e2e** (`mission.mjs`): ввести миссию и строку роли → перезагрузка — на месте; подсказка на роли; блок в панели по настройке; шаг 4 обзора.
**Не делаем.** Несколько миссий, историю правок, оформление текста (жирный и т. п.).
