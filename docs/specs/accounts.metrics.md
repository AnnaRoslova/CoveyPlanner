## Спека (шаг 1, 2026-10-22)

⚠ Решила сама (в спеке помечены «(предложение)» там, где нужен ответ Анны — раздел 18):
- Порядок этапов: перенос данных (этап 1) — раньше входа, отдельно, чтобы рискованный шаг проверялся сам по себе.
- `UserId` — GUID (имя файла не выдаёт соседей и число пользователей).
- Код хранится как HMAC-SHA256 с ключом вне `accounts.db` (а не просто SHA-256: 6 цифр перебираются за миллисекунды).
- CSRF — `SameSite=Lax` + обязательный заголовок `X-Planner` + проверка `Origin`, без antiforgery-токенов (API только JSON, CORS не включаем).
- Токен приглашения — во фрагменте ссылки (`#`), чтобы не попадал в журналы сервера и `Referer`.
- IP-адреса не храним (ни у сессий, ни у кодов); лимит по адресу — только в памяти.
- Служебные скрипты (`backup.ps1`, `install.ps1`) — по ключу из файла `local.key`, а не «с localhost без входа» (за прокси всё приходит с localhost).
- Общий лимит API — 600 запросов в минуту на пользователя.
- Назначение других администраторов, смена почты — не делаем; поэтому единственный администратор не может удалить свой аккаунт.
