## N6. «🛠 Проекты» — отдельное место для проектов

Статус: решения Анны (2026-10-15) — без отдельного «ок»; открытые вопросы решены мной (помечены ⚠ — Анна посмотрит при проверке).

**Цель.** Проекты на экране не отличались от мыслей: проект цели падал в «неразобранное», книга с шагами лежала среди идей.
Проекту — своё место; лента — только мысли.

**Решения Анны**
- **N6.1.** Иконка 🛠 вверху рядом с 🫙 → все **открытые проекты** (проект не выполнен, не в корзине): «☑ N/M», разворачивание шагов,
  перетаскивание шагов в дни, «+ проект», фильтр по категории.
- **N6.2.** В ленте проекты **не показываются** (лента — только мысли). Категория у проекта остаётся — для фильтра и группировки «Выполненного».
- **N6.3.** Мысль становится проектом **явно**: кнопка «🛠 Сделать проектом» в окне или первый «+ шаг». Плашка
  «„…“ теперь проект · 🛠 Проекты · Вернуть».
- **N6.4.** Проект, созданный из окна цели (G3), — сразу в «🛠 Проекты» (не в «неразобранное»).
- **N6.5.** Проект в дне — маленькая 🛠 и тонкая полоска прогресса.

**Мои решения (открытые вопросы)**
- **N6.6. ⚠ Модель: флаг `Tasks.IsProject`.** «Проект = дело с шагами» без флага не выдерживает самих решений Анны: кнопка «Сделать проектом»
  делает проект **без шагов**, а удаление последнего шага само переносило бы проект обратно в ленту — переход без явного действия (П4).
  Поэтому проект — по-прежнему дело (та же строка `Tasks`, никакой новой сущности), а `IsProject` — явная запись о явном переходе
  (следствие 1 model-principles). Инвариант: у дела есть шаги (в любом состоянии) ⇒ `IsProject = true`; сервер ставит флаг сам при любом
  появлении шага (первый «+ шаг», поле «Проект» другого дела, G3, возврат шага из корзины). Шаг и занятие цели проектом не бывают (S1, G4).
  Проект шагом не бывает (даже без шагов) — поле «Проект» у него неактивно: «это проект».
- **N6.7. ⚠ Все шаги удалены** — дело остаётся проектом «☑ 0/0» в «🛠 Проекты» (можно добавить шаги). Перестать быть проектом — явно:
  в окне проекта без шагов (корзина не в счёт) тихая кнопка «🛠 больше не проект»: проект без дня возвращается в ленту (в свою категорию,
  наверх — как любой возврат), в дне — остаётся обычным делом. Пока шаги есть, кнопки нет.
- **N6.8. ⚠ Где «экран».** «🛠 Проекты» — режим правой панели вместо ленты (кнопка 🛠 переключает, в шапке панели «← лента»): шаги
  тащат прямо в дни недели, как мысли из ленты (на экране поверх недели дней не видно). Режим запоминается в браузере.
  Внизу панели — те же «✓ выполненное» и корзина.
- **N6.9. Что в списке.** Проекты без родителя, `IsProject`, состояние «в ленте» или «в плане» (с днём или без). Группы — по категориям
  в порядке ленты, «без категории» в конце (заголовок группы — как у категории ленты, со счётчиком); фильтр «все категории ▾» оставляет
  одну группу. В группе — сначала проекты без дня (в порядке ленты), потом с днём — по дате, с меткой «Чт 12 окт». ⚠ Ручного порядка
  в панели нет (перетаскивание проекта внутри панели — только в другую группу = сменить категорию).
- **N6.10.** Строка проекта — как в ленте: чекбокс (проект без дня — «выполнено в ленте» с плашкой D3, в дне — обычная отметка), «☑ N/M»,
  «⌄» — шаги с «+ шаг», клик — окно. Проект тащат в день (как мысль), из дня — в группу панели (снять с дня, в эту категорию),
  на корзину. Шаги — как в раскрытом списке ленты (в день, на цель, порядок).
- **N6.11. «+ проект».** Строка вверху панели: название + Enter — проект без дня в категории фильтра (или «без категории»), наверху группы;
  можно сразу «+ шаг».
- **N6.12. ⚠ Поиск.** Поиск ленты ищет только мысли; если совпали проекты (название или шаг) — внизу тихая строка «🛠 в проектах: N»,
  клик — панель проектов с тем же текстом. В панели проектов — свой поиск (название проекта и шагов, совпавший шаг — проект раскрыт).
- **N6.13. ⚠ Поле «Проект»** (в окне дела и цели) предлагает **только проекты** (открытые, без родителя, из ленты и плана любой недели) + текущий.
  Обычное дело проектом через чужое поле не становится — только кнопкой, первым «+ шаг» или (N2) броском дела на дело.
- **N6.14. ⚠ «Вернуть» на плашке N6.3.** Кнопкой — снимает флаг; первым «+ шаг» — снимает флаг **и удаляет этот шаг** (одно действие —
  одна отмена). Мысль возвращается в ленту на своё место. «🛠 Проекты» на плашке — открыть панель на этом проекте.
- **N6.15.** G3: проект цели — сразу `IsProject`, без категории; плашка «Проект «…» — в 🛠 Проектах · 🛠 Проекты».
- **N6.16. В дне.** У проекта — 🛠 перед подписью «☑ 2/5» и полоска прогресса 2px внизу строки (доля шагов в счёте, цвет `--b-deep`
  с прозрачностью; у проекта «☑ 0/0» полоски нет). Занятие цели с проектом цели (G4) — без 🛠 и полоски: оно не проект.
- **N6.17. ⚠ Миграция.** `IsProject = 1` у каждого дела, у которого есть хотя бы один шаг (в любом состоянии, включая корзину). Проекты Анны
  уходят из ленты в «🛠 Проекты» сами — с теми же категориями. Число — в отчёте установки (metrics).
- **N6.18.** «Выполненное», привычки, отчёт — без изменений (проект — то же дело).

**Модель/миграция.** `Tasks.IsProject` (bool, по умолчанию false) + заполнение по N6.17. API: `PUT /api/tasks/{id}/project {isProject}`;
`CreateTaskRequest.IsProject`; `TaskDto.IsProject`; `BoardDto.PlannedProjects` — открытые проекты в плане (любая неделя) и их шаги в `Steps`.

**e2e** (`projects.mjs`): кнопка 🛠 — панель, лента скрыта; проекты из ленты (миграция/шаги) — в панели, не в ленте; «Сделать проектом» —
мысль ушла, плашка, «Вернуть»; первый «+ шаг» у мысли — проект, «Вернуть» убрал и шаг; «+ проект» с фильтром категории; шаг из панели
в день; проект в день и обратно в группу; 🛠 и полоска в дне; поиск ленты «🛠 в проектах: 1»; G3 — проект в панели; «больше не проект».

**Не делаем.** Ручной порядок проектов в панели, архив проектов отдельно от «Выполненного», статусы проектов («на паузе» и т. п.).

## N1. Подсветка неразложенного

**Цель.** Сразу видеть в левой панели цели, у которых на неделе ещё не все занятия стоят в днях: план недели «недособран».

**Термины.** *Разложено* — занятие цели (не в корзине) стоит в дне этой недели (выполненное или нет) **или** выполнено без дня
(галочка цели). *Не разложено* — «раз в неделю» минус разложенные (не меньше 0).

**Правила**
- **N1.1.** Цель подсвечена, если не разложено > 0 и цель не выполнена. Всё разложено или выполнено (норма закрыта) — подсветки нет.
- **N1.2.** Подсветка тихая: мягкая подложка строки цветом акцента темы (≈ 12–15 %, как «сегодня», но слабее) и тонкая полоска слева
  (предложение). Никаких красных/тревожных цветов, мигания, значков «!».
- **N1.3.** Подсказка при наведении на строку цели: «не разложено: 1 из 2» (сколько не разложено из «раз в неделю»).
  У свёрнутых целей («свернуть все цели») подсветка остаётся, подсказка — та же.
- **N1.4.** Считается по показанной неделе. Прошлые недели (неделя закончилась) — не подсвечиваются (разложить уже некуда) (предложение).
- **N1.5.** «Можно несколько раз в день»: разложенными считаются все занятия в днях, даже два в одном дне.
- **N1.6.** Под ролью «ещё дела: N» — без изменений.
- **N1.7.** Только вид: ничего не хранится, считается на клиенте по `WeeklyGoalDto.Sessions` (у занятия есть день и отметка).

**Крайние случаи**
- Цель 3 раза: 2 занятия в днях, одно выполнено без дня → разложено 3 → подсветки нет.
- Цель 2 раза: одно занятие в дне, второе — в корзине → не разложено 1.
- Цель с выбранными днями («Повтор») — занятия встают в дни сами, обычно подсветки нет; убрали одно в корзину — появилась.
- Занятие перенесли на другую неделю — у цели этой недели оно больше не считается (оно у цели той недели).
- Цель «раз в неделю», занятие без дня (мысль из ленты, ставшая целью) — подсвечена, пока его не поставили в день.

**Интерфейс.** Класс строки `.unplaced`; переменные темы `--unplaced-bg` (подложка), `--unplaced-bar` (полоска) — в каждой теме своё значение.
**Контраст:** `themes-contrast.mjs` — текст цели, процент и «☑ N/M» на подложке `--unplaced-bg` во всех 11 темах: основной текст AA (4.5:1),
второстепенный не ниже 3:1; полоска от фона панели — не ниже 1.5:1 (тихая, но заметная).

**Модель/миграция.** Нет.

**e2e** (`goal-unplaced.mjs`)
1. Цель 2 раза без занятий — подсвечена, подсказка «не разложено: 2 из 2»; бросили цель на день — «1 из 2»; на второй день — подсветки нет.
2. Занятие в корзину — подсветка вернулась; «Вернуть» — исчезла.
3. Галочка цели (выполненное без дня) закрыла норму — подсветки нет.
4. Прошлая неделя — подсветки нет; «свернуть все цели» — подсветка остаётся.
5. `themes-contrast.mjs` — проверки выше во всех темах.

**Не делаем.** Подсветку дней, счётчик в шапке недели, уведомления, подсветку прошлых недель.

## N2. Дело на дело = шаг

**Цель.** Сделать дело шагом другого дела одним жестом, без окна. Снимает пункт «не делаем» в tasks-steps-done.md
(«Перетаскивание дела на другое дело, чтобы сделать его шагом»).

**Правила**
- **N2.1.** Дело (из дня, из ленты, шаг из раскрытого списка) бросили на **середину** строки другого дела — в дне или в ленте — оно становится
  шагом этого дела. Это тот же переход, что выбор в поле «Проект» (S6–S10): мысль из ленты уходит из ленты и становится шагом без дня, дело в дне
  остаётся в своём дне (с подписью «↳ …»), шаг другого проекта переходит к этому (S10), занятие цели остаётся занятием (S8).
- **N2.2.** Верх и низ строки (по 30 % высоты) — как сейчас: порядок в дне или в ленте (линия вставки).
- **N2.3.** Подсветка различает два броска: середина — строка-цель обведена и подкрашена, у призрака подпись «сделать шагом «Ремонт»»;
  край — только линия вставки между строками, строка не подсвечивается.
- **N2.4. Нельзя** (середина строки не принимает бросок, работает как край — порядок):
  на шаг (один уровень), на само себя, если у перетаскиваемого есть свои шаги («у дела есть шаги — оно само проект»), на занятие цели
  (у него шаги проекта цели, G4), на дело в корзине/выполненное в ленте (их на экране нет). Цель (из левой панели) на дело — не принимается.
- **N2.5.** Бросили шаг на строку **своего** проекта — как сейчас S20 (снять с дня, остаться шагом).
- **N2.6.** Плашка «„Краска“ теперь шаг „Ремонт“ · Вернуть» (6 с, у корзины — как плашки ленты). «Вернуть» — убрать из проекта и вернуть дело
  на прежнее место: в свою категорию и позицию ленты или в свой день и позицию (для шага другого проекта — обратно к прежнему проекту).
- **N2.7.** Изменение уходит на сервер сразу (как «Проект»), «Вернуть» — обратная операция (не отложенная отправка).

**Крайние случаи**
- Дело со временем «15:00» из дня на дело в ленте — становится шагом, остаётся в своём дне со временем.
- Мысль на дело в дне — шаг без дня; в дне не появляется (видно в раскрытом списке проекта).
- Дело с шагами тащат на другое дело — середина не принимает (подсказки «сделать шагом» нет), бросок по краю — порядок.
- Тащат дело на его же шаг — середина шага не принимает (шаг не бывает проектом).
- Проект свёрнут/развёрнут — бросок на середину строки проекта работает так же; новый шаг — в конец списка.
- Поиск в ленте включён — перетаскивание в ленте выключено (как сейчас), N2 в ленте не работает.
- Касание: долгое нажатие — перетаскивание, середина/край — так же по положению пальца.

**Модель/миграция.** Нет (API `PUT /api/tasks/{id}/parent` есть; для «Вернуть» — `move` на прежнее место).
**Интерфейс.** Новая зона `task` на строках дел (data-drop-middle, как у строк целей): принимает `day`, `someday`, `step`; клиент проверяет N2.4 до броска
(у призрака «нельзя» не показываем — середина просто не подсвечивается). Тексты: подсказка у призрака «сделать шагом «…»».

**e2e** (`dnd-make-step.mjs`)
1. Дело из дня на середину другого дела в дне — шаг, «↳ …», «☑ 0/1» у проекта; плашка → «Вернуть» — снова отдельное дело на прежнем месте.
2. Мысль из ленты на середину мысли — ушла из ленты, в раскрытом списке проекта; «Вернуть» — на прежнем месте категории.
3. На верх/низ строки — порядок, шагом не стала.
4. Запреты N2.4: на шаг, на занятие цели, дело с шагами — середина не подсвечивается, бросок — порядок.
5. Подсветка: середина — обводка строки и подпись у призрака; край — только линия.

**С N6.** Мысль, на которую бросили дело, становится проектом (как первый «+ шаг», N6.3): уходит из ленты в «🛠 Проекты», плашка
«„Краска“ теперь шаг „Ремонт“ · Вернуть» (Вернуть снимает и флаг проекта, если он появился от этого броска). Бросить можно и на строку
проекта в панели «🛠 Проекты» (шаг из дня).

**Не делаем.** Многоуровневые шаги (см. N3), перетаскивание проекта целиком «в» другой проект, создание проекта из двух мыслей сразу.

## N3. Вложенность шагов глубже одного уровня — анализ (не реализация)

**Что сейчас:** один уровень (S1). На одном уровне держатся: счётчик «☑ N/M», автоотметка S12/R4′, корзина проекта целиком (S23–S27),
раскрытие строки (R1/R5), «Проект» и N2, шаги цели (G1–G10), «Выполненное» («14 шагов · 5 недель»).

**Во что обойдётся глубина (дерево):**
| Место | Сейчас | С деревом |
|---|---|---|
| Модель | `ParentId` + `StepOrder` | то же поле, но запрет «шаг шага» снимается; нужна защита от циклов (A шаг B, B шаг A) при каждом «Проект»/N2; запросы шагов становятся рекурсивными (CTE в SQLite есть, но EF — только сырым SQL или загрузкой целиком) |
| Счётчик «☑ N/M» | шаги одного уровня | что считать — листья или прямых детей? «2/5» при 3 уровнях неочевиден; у каждого узла свой счётчик |
| Автоотметка S12 | последний шаг → родитель | каскад вверх по всем уровням; R4′ (занятие) — через сколько уровней? S13 «сам не открывается» на каждом уровне |
| Корзина S23–S27 | проект и его шаги одним TrashedAt | всё поддерево; возврат шага — возвращает цепочку родителей; «удалить навсегда» каскадом — ок, но восстановление середины дерева запутывается |
| Занятия целей среди шагов | не в счёте, «N занятий» | на каком уровне их считать, в какой счётчик |
| Перетаскивание | дело→дело = шаг (N2), шаг→свой проект = снять с дня | бросок на шаг становится допустимым — у каждой строки списка шагов свой «сделать шагом», риск случайно закопать дело на 3 уровня; нужна индикация глубины |
| UI | строка + раскрытый список | вложенные списки в узкой колонке дня (~130 px) — отступы съедают ширину; на телефоне (этап 3) — ещё хуже |
| «Выполненное», отчёт (N5) | «14 шагов» | суммирование по дереву, глубина в CSV |

**Рекомендация:** **не делать.** Один уровень + проекты + цели покрывают задачи Анны (ремонт, книга, курс, подготовка к собесу): то, что тянет
на третий уровень, — обычно отдельный проект (дело ленты в той же категории) или цель. Цена — заметная: рекурсия в модели и запросах,
каскады в автоотметке и корзине, неочевидные счётчики, теснота в узких колонках. Если понадобится «группировка шагов» — дешевле
**разделитель внутри списка шагов** (подзаголовок без отметки, просто строка-метка), чем дерево. Решение — за Анной (вопрос В-N3).

## N4. Дело на следующую неделю без дня

**Цель.** «Сделаю на следующей неделе, день пока не знаю»: убрать дело с этой недели, чтобы оно ждало на следующей — видно, но не в дне.

**Что уже есть.** Перетаскивание дела из ленты или из дня на роль слева уже делает его **разовой целью недели** с этим делом как занятием
(`POST /api/goals/from-task`). Если перед этим перелистнуть неделю стрелкой «›», цель создаётся на следующей неделе.
Найденная дыра: дело **из дня** при этом остаётся в своём дне этой недели, а цель — на следующей (занятие вне недели своей цели) — это надо
исправить в любом варианте: дело из дня, ставшее целью другой недели, теряет день (становится занятием без дня).

**Проверка по model-principles.md.**
- П2 (нет автосвязей), П4 (явное действие, вещь переезжает целиком) — вариант «как цель» не нарушает: явная кнопка, дело — то же самое дело.
- **П1 (у каждой сущности один смысл) — нарушает мягко:** цель — «большой камень» роли с нормой «раз в неделю», а здесь цель становится
  **контейнером для одного дела**, чтобы показать его «на неделе без дня». Последствия: «камней» в шапке становится больше («камней: 2 из 9»),
  процент занятий плывёт, цель-однодневка появляется в окне цели с «раз в неделю», проектом, «копить»; удаление «цели» — по правилам цели
  (выполненное остаётся, невыполненное — в корзину).
- Дело **без роли** цель создать не может (у цели хотя бы одна роль).

**Варианты**
- **А — как просила Анна: разовая цель («камень»).** Кнопка «→ на следующую неделю (без дня)» = `from-task` на следующую неделю в первую роль дела
  (без роли — в роль, которую спросить списком, или в «Я сама» (вопрос)). Плюс — переиспользует готовое. Минусы — П1, «камни» и проценты.
- **Б — рекомендую: «на неделе, без дня» как место дела, без цели.** Новое поле `Tasks.PlannedWeek` (понедельник) у дела с `PlannedDate = null`:
  дело запланировано на неделю, день не выбран. Показывается **в левой панели следующей недели под своей ролью** отдельной тихой строкой
  «на неделе: Купить подарок» (над «ещё дела»), без роли — в отдельном блоке «без роли» внизу левой панели; перетаскивается в день,
  обратно в ленту, на цель (станет занятием). Камнем не становится, «камни» и проценты не трогает. Если Анна хочет, чтобы это всё-таки был камень, —
  перетащить строку на роль (существующее «дело → цель»), это явное действие.
  Минусы Б: новое поле и миграция, новое место на экране, правила для недели без дня (переход на следующую неделю, если день так и не назначили?).
- **В — минимальный:** только исправить дыру из «Что уже есть» и добавить кнопку как А, но для дел без роли кнопка неактивна с подсказкой
  «сначала роль». Дёшево, П1 остаётся нарушенным.

**Правила (для выбранного варианта — пишу Б, как рекомендую; А/В — в вопросах)**
- **N4.1.** В окне дела и в меню строки (у дела в дне, у мысли в ленте) — «→ на следующую неделю (без дня)»: дело получает `PlannedWeek` =
  понедельник следующей недели (от показанной), `PlannedDate` и время убираются; мысль из ленты уходит из ленты (State = Planned).
  Плашка «Перенесено на неделю 12–18 окт · Показать».
- **N4.2.** В левой панели недели — под каждой ролью строка-список «на неделе: N ▸» (дела этой недели без дня с этой ролью); без роли — блок
  «на неделе без роли» внизу. Раскрыт по умолчанию, если есть дела (вопрос). Клик по делу — окно; перетаскивание — в день, в ленту, на цель, на роль.
- **N4.3.** Перетаскивание дела на «›» и потом на роль слева — по-прежнему «дело → цель» (камень) этой роли (как сейчас), с исправлением дыры:
  дело из дня теряет день. А чтобы «на неделю без дня» перетаскиванием — бросить на строку «на неделе» роли (новая зона).
- **N4.4.** Неделя прошла, дело без дня так и осталось — остаётся на той неделе (видно, если вернуться); на текущую не переезжает само (П2),
  в недельном обзоре (этап 2 CLAUDE.md) — среди невыполненного (позже).
- **N4.5.** Шаги и занятия: шаг проекта — тоже можно «на неделю без дня» (видно в списке проекта с меткой «нед. 12 окт»); занятие цели —
  кнопка неактивна (у занятия своя неделя — неделя цели).

**Модель/миграция (Б).** `Tasks.PlannedWeek` (DateOnly?, понедельник), индекс `(State, PlannedWeek)`; инвариант: `PlannedWeek` только при
`PlannedDate = null` и State Planned/Done. Миграция: новых данных нет — столбец пустой.

**e2e** (`next-week.mjs`): кнопка в окне дела и в меню строки; дело исчезло из дня, видно слева на следующей неделе под ролью; без роли — в блоке
«без роли»; перетаскивание оттуда в день; «›» + роль = камень, дело из дня теряет день (исправление дыры).

**Не делаем.** Автоперенос неразложенных дел на следующую неделю, «на месяц без дня», напоминания.

## N5. Отчёт за период

**Цель.** Посмотреть, что сделано за неделю/месяц/год: привычки и постоянные цели (план и факт), «Выполненное» по категориям — и выгрузить в Excel.

**Правила**
- **N5.1.** Вход — кнопка «📊» в шапке недели рядом с 🫙 (предложение); экран — поверх недели, как «Копилки». Только чтение.
- **N5.2.** Период: «неделя» (показанная), «месяц» (календарный, текущий; стрелки ‹ › листают), «N месяцев» (последние N, по умолчанию 3, N = 2…12),
  «год» (календарный, стрелки), «свой» (с — по, календарь). По умолчанию — текущий месяц (предложение).
- **N5.3. Привычки и постоянные цели** (серии с «каждую неделю», и копят, и нет; законченные — если в периоде были цели): строка на серию —
  название, роль(и), **план** = сумма «раз в неделю» целей серии за недели периода, **факт** = выполненные занятия (скрепки, включая скрепки удалённых
  целей, C2) с днём в периоде, процент факт/план; у привычек — 🔥 на конец периода (для справки).
  Неделя входит в период, если в периоде её **четверг** (как месяцы привычек) — тогда «месяц» не делит недели пополам; факт считается по дням
  занятий внутри этих недель (предложение; альтернатива — в вопросах).
- **N5.4. Разовые цели** — одной строкой «разовые цели: камней N, выполнено M» (предложение; подробно — нет).
- **N5.5. «Выполненное» за период** — группы по категориям, как на экране «Выполненное» (V3), но только дела с днём отметки в периоде:
  «📚 Книги — 3: Дюна, Солярис, Атомные привычки»; «без категории» — в конце.
- **N5.6. CSV** — кнопка «Скачать CSV»: файл `CoveyPlanner-отчёт-2026-10-01—2026-10-31.csv`, UTF-8 с BOM, разделитель «;», строки через CRLF,
  даты `ДД.ММ.ГГГГ`, числа без разрядов. Два блока в одном файле с заголовками («Привычки и постоянные цели», «Выполненное»), колонки:
  `Раздел;Название;Роль/категория;План;Факт;%;Дата` (в «Выполненном» — `Раздел;Категория;Дело;Дата отметки;Шагов`). Кавычки — по правилам CSV
  (`;`, `"` и перевод строки внутри значения — в кавычках, `"` удваивается).
- **N5.7.** Данные только читаются: никаких записей, генерации недель постоянных серий (отчёт не создаёт цели будущих недель — считает только то,
  что есть; недели без цели — без плана, как в привычках H8).

**Крайние случаи**
- Период в будущем — пусто, план по уже созданным целям будущих недель (их создаёт только открытие недели).
- Серия с правкой нормы в середине периода — план по нормам своих недель (H7).
- Каникулы — в отчёте не вычитаются (план как был), отметка «🏖» у недели в подсказке (предложение).
- Дело отметили, сняли и отметили снова — дата последней отметки (V5).
- Пустой период — «за этот период ничего нет», CSV всё равно скачивается с заголовками.
- Очень длинный период (годы) — один запрос на сервере, без постраничности.

**Модель/миграция.** Нет. API: `GET /api/report?from=&to=` (JSON) и `GET /api/report.csv?from=&to=` (файл); сервис `ReportService` в Core
(чистая сборка по уже существующим запросам: скрепки, нормы недель, «Выполненное»).

**e2e** (`report.mjs`): экран открывается, периоды переключаются, числа совпадают с API; CSV скачивается, начинается с BOM, «;», открывается
как UTF-8 (кириллица цела); пустой период.

**Не делаем.** Графики, сравнение периодов, PDF, отправку по почте, отчёт по ролям/квадрантам (этап 4 CLAUDE.md), запись настроек отчёта на сервере.
