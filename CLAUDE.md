# CoveyPlanner — ТЗ и правила проекта

Личный планировщик по мотивам недельного листа Стивена Кови («7 навыков высокоэффективных людей», глава 3 «Главное — вперёд»)
плюс лента дел «когда-нибудь», из которой задачи перетаскиваются в план.

Владелец — Анна, C#-разработчик. Код должен быть понятным, идиоматичным C#, чтобы его было легко дорабатывать руками.

---

## 1. Цели и ограничения

- Сейчас: пользоваться с компьютера через браузер (сервер крутится локально).
- Потом: iPhone (PWA, «На экран Домой») и веб. Нативное iOS-приложение НЕ делаем.
- Ничего платного. Никаких сторонних облаков/BaaS (Supabase, Firebase и т.п.) — приложение независимое, данные у владельца.
- Путь роста: localhost → телефон через Tailscale/ZeroTier к домашнему ПК → (опционально) VPS/Docker. Код при этом не меняется.

## 2. Стек

- .NET 10 (LTS).
- `Planner.Server` — ASP.NET Core Web API (minimal API или контроллеры), EF Core + SQLite (один файл БД), миграции EF.
  Сервер также хостит клиент (Blazor WASM hosted).
- `Planner.Client` — Blazor WebAssembly, PWA (manifest + service worker), интерфейс на Razor/C#. JS — только точечно через JS interop, если без него никак.
- `Planner.Shared` — DTO и контракты API.
- `Planner.Core` — доменная модель и логика (без зависимостей от ASP.NET / EF).
- `Planner.Tests` — xUnit, тесты на доменную логику и API (WebApplicationFactory).
- UI-библиотеки: по возможности без тяжёлых (MudBlazor и т.п. — только если реально упрощает). Своя аккуратная CSS.
- Хранилище за интерфейсом (репозиторий/сервис), чтобы можно было сменить SQLite → PostgreSQL.
- Авторизация на этапе localhost не нужна; заложить место под ASP.NET Identity на будущее (когда сервер будет смотреть в сеть).

## 3. Экран (десктоп)

Три зоны слева направо:

### 3.1. Слева — «Роли и цели» (недельный лист Кови)
- Сверху блок **«Затачивание пилы»**: 4 измерения — тело, ум, дух, общение/эмоции; у каждого 0..n целей на неделю.
- Ниже — список **ролей** (пользовательские, редактируемые: переименовать, цвет, порядок, добавить/удалить).
  Стартовые примеры: «Я сама», «Семья», «Работа», «Дом».
- У каждой роли — 1–3 **цели на неделю** («большие камни»). Цель можно перетащить в конкретный день.

### 3.2. Центр — неделя
- 7 колонок-дней (Пн–Вс), навигация «← неделя →», «Сегодня».
- **Сетки часов НЕТ** (решение после просмотра прототипа: по духу Кови — гибкость и приоритеты, а не расписание по часам).
  День — это просто список дел в ручном порядке.
- У дела может быть **необязательное время** (реальная встреча: «15:00 Стоматолог») — показывается маленькой меткой-пилюлей на карточке.
  Дела со временем в списке дня автоматически встают по времени; дела без времени — в ручном порядке. Длительности нет.
- Задача: отметка «выполнено», редактирование по клику (название, заметки, роль, время, квадрант), цвет роли точкой/кружком-чекбоксом,
  метка «камень», если дело связано с целью недели, необязательная отметка квадранта I–IV.

### 3.3. Справа — лента «Когда-нибудь» (узкая полоса, ~260–300px)
- **Никаких сроков и дат** в ленте. Это склад мыслей: может сделаю на следующей неделе, может через 10 лет, может передумаю.
- **Категории** — ОДИН уровень (без подкатегорий). **Каждое дело в ленте обязательно принадлежит категории. Системной категории «Входящие» НЕТ.** Категории ленты — НЕ то же самое, что роли Кови (роли = «кто я», категории = «о чём дело»).
- Вид — **аккордеон**: заголовок категории с серым счётчиком дел; клик раскрывает/сворачивает. Раскрыто может быть **сколько угодно** категорий одновременно; состояние раскрытия запоминается.
- Вся лента — одна прокручиваемая колонка: колесо мыши листает и внутри раскрытых категорий, и по всем категориям подряд.
- Сверху — **поиск** (фильтрует по всем категориям, раскрывая совпадения).
- В конце каждой раскрытой категории — строка «+ добавить»: ввод текста + Enter, без форм. Новое дело — наверх категории.
- Сверху ленты — быстрое поле «Записать мысль…» + выбор категории (по умолчанию последняя использованная).
- У категории может быть эмодзи-иконка (необязательно).
- Если категорий ещё нет — вместо поля подсказка «создайте первую категорию».
- Дело, созданное прямо в плане, категории не имеет, пока лежит в плане. При возврате в ленту: перетаскиванием — в ту категорию, куда бросили;
  другим способом (обзор недели, восстановление из корзины, удаление цели) — в исходную категорию, а если её нет — спросить категорию маленьким выпадающим меню.
- Порядок дел внутри категории — ручной (drag). Дела можно перетаскивать между категориями.
- Внизу — «+ категория».
- **Корзина**: маленькая серая иконка в самом низу ленты, без яркого счётчика, не отвлекает. Клик — небольшое всплывающее окно со списком удалённого: «вернуть» / «удалить навсегда» / «очистить всё». Хранится бессрочно, чистится только вручную.

## 4. Перетаскивание (ключевая фича)

- Лента → день, лента → цели роли.
- План → обратно в ленту (задача снова без даты, в своей исходной категории).
- Внутри плана: между днями и внутри дня (порядок).
- Внутри ленты: переупорядочивание и перенос между категориями.
- Реализация на **pointer events** (не HTML5 DnD — он плохо работает на iOS Safari): мышь — сразу, палец — после долгого нажатия (~300 мс). Призрак карточки, подсветка зоны сброса, автоскролл ленты и недели у краёв.
- Изменения сохраняются на сервер сразу (оптимистичное обновление UI).

## 5. Модель данных (черновик)

- `Task` — Id, Title, Notes?, CategoryId? (для ленты), RoleId?, Quadrant? (1–4),
  State: Someday | Planned | Done | Trashed,
  PlannedDate? (DateOnly), StartTime? (TimeOnly — необязательная метка времени, без сетки), без DurationMinutes,
  SortOrder, CreatedAt, CompletedAt?, TrashedAt?, PreviousState (для возврата из корзины).
- `Category` — Id, Name, Emoji?, SortOrder, IsExpanded. Без IsSystem/«Входящих».
- `Role` — Id, Name, Color, SortOrder, IsSharpenSaw (или отдельная сущность для 4 измерений).
- `WeeklyGoal` — Id, RoleId, WeekStart (DateOnly, понедельник), Title, IsDone, SortOrder, TaskId? (если запланирована).
- Задача, вынесенная из ленты в план, — это та же сущность (меняется State/PlannedDate), а не копия; при возврате в ленту возвращается в свою категорию.

## 6. Мобильная раскладка (этап 2, но не ломать заранее)

- Узкий экран: один день (свайп между днями) или неделя списком; роли и цели — отдельной вкладкой.
- Лента — выезжающая шторка сбоку; перетаскивание из шторки в день.

## 7. Этапы

1. **MVP**: каркас решения, БД, API, десктопный экран (роли/цели, неделя из 7 дней-списков, лента с категориями, поиском, корзиной), перетаскивание, сохранение.
2. **Недельный обзор**: в конце недели — экран с невыполненным; по каждому: перенести / вернуть в ленту / удалить; там же выбор «больших камней» на следующую неделю.
3. PWA + мобильная раскладка + проверка на iPhone.
4. Повторяющиеся дела, квадранты I–IV со статистикой за неделю, архив выполненного.
5. (Опционально) доступ с телефона через Tailscale, Docker-образ, Identity.

## 8. Дизайн

Образец — `docs/design-mockup.html` (открыть в браузере; все цвета и стили — в его CSS, брать оттуда). Утверждённый вариант: структура **«в точку»**, палитра **«Лотос»**.
Ощущение — уютный бумажный блокнот (bullet journal), НЕ офисный/табличный.

- Фон страницы — градиент «как небо»: `#f8d5da → #d7eee7 → #b9e0d6` (розовый → мятная бирюза).
- Три зоны — полупрозрачные плавающие панели со скруглением ~22px, без рамок.
  Левая (роли) — самая светлая и прозрачная (едва заметный шалфей + blur); правая (лента) — чуть розоватая.
- Дни — «страницы в точку»: фон с точечной сеткой бирюзового оттенка, скругление ~18px.
  Сегодня — очень нежная розовая подсветка (≈4%) и тонкая бледная обводка, бейдж «сегодня» пастельный; выходные — едва заметный бирюзовый оттенок (≈5%). Никаких резких контрастных выделений.
- Записи — строки, НЕ карточки: квадратный чекбокс цвета роли, текст, пилюли «время» (бирюзовая) и «камень» (розовая). При наведении — лёгкая розовая подложка.
- Шрифты: **Nunito** — основной; **Caveat** (рукописный) — названия дней недели; **Lora** — заголовки панелей и недели.
- Палитра «Лотос»: текст `#3e4d52`, приглушённый `#88999c`, бледный `#c3cfd0`, линии `#efe6e7`;
  розовый `#f2a4ab` / мягкий `#fdecee` / глубокий `#cf6f79`; бирюза `#9fd6c9` / `#e8f6f2` / `#3f9585`.
- Цвета ролей: `#f29ea6 #f4c3cf #6fbfae #94b4b5 #a8dcd0 #f7d3db #8ac2c4 #e9b0b8` (+2 в том же духе).
- Иконки категорий — эмодзи. Минимум линий, больше воздуха.

## 9. Правила работы

- git с первого шага, небольшие осмысленные коммиты.
- Перед каждым «готово» — `dotnet build` без ошибок и `dotnet test` зелёный.
- Проверять UI в браузере (`dotnet run --project Planner.Server`), особенно перетаскивание.
- Не добавлять платные сервисы и внешние облачные зависимости.
- Комментарии и UI — на русском; идентификаторы в коде — на английском.
- README с инструкцией: как запустить, где лежит файл БД, как сделать бэкап.
