# CoveyPlanner — ТЗ и правила проекта

Личный планировщик по мотивам недельного листа Стивена Кови («7 навыков высокоэффективных людей», глава 3 «Главное — вперёд»)
плюс лента дел «когда-нибудь», из которой задачи перетаскиваются в план.

Владелец — Анна, C#-разработчик. Код должен быть понятным, идиоматичным C#, чтобы его было легко дорабатывать руками.

---

## Принципы модели

1. **У каждой сущности один смысл.** Цель — цель, категория ленты — папка, привычка — постоянная цель пилы.
2. **Никаких автоматических связей** (по категории, по названию и т.п.): что с чем связано, решает только явное действие.
3. **Ничего не превращается во что-то другое переключателем** (не бывает «вида», меняющего смысл сущности).
4. **Переход — только явным действием, и вещь переезжает целиком**, а не живёт в двух местах (мысль из ленты → дело в плане — та же
   сущность; удалили привычку — её цель и дела не трогаются).

## 1. Цели и ограничения

- Сейчас: пользоваться с компьютера через браузер (сервер крутится локально).
- Потом: iPhone (PWA, «На экран Домой») и веб. Нативное iOS-приложение НЕ делаем.
- Ничего платного. Никаких сторонних облаков/BaaS (Supabase, Firebase и т.п.) — приложение независимое, данные у владельца.
- Путь роста: localhost → телефон через Tailscale/ZeroTier к домашнему ПК → (опционально) VPS/Docker. Код при этом не меняется.

## 2. Стек

- .NET 10 (LTS).
- `Planner.Server` — ASP.NET Core Web API (minimal API или контроллеры), EF Core + SQLite, миграции EF. Хранилище (`docs/specs/accounts.md`, D): папка данных `%LOCALAPPDATA%\CoveyPlanner` —
  общая `accounts.db` (аккаунты) и **отдельный файл SQLite на пользователя** `users\<id>.db` (схема данных одна; `PlannerDbContext` открывается
  на файл того, чей запрос), `keys\`, `local.key`, `settings.json` (вне git), снимки `backups\planner-…\` — всё целиком.
  Сервер также хостит клиент (Blazor WASM hosted).
- `Planner.Client` — Blazor WebAssembly, PWA (manifest + service worker), интерфейс на Razor/C#. JS — только точечно через JS interop, если без него никак.
- `Planner.Shared` — DTO и контракты API.
- `Planner.Core` — доменная модель и логика (без зависимостей от ASP.NET / EF).
- `Planner.Tests` — xUnit, тесты на доменную логику и API (WebApplicationFactory).
- UI-библиотеки: по возможности без тяжёлых (MudBlazor и т.п. — только если реально упрощает). Своя аккуратная CSS.
- Хранилище за интерфейсом (репозиторий/сервис), чтобы можно было сменить SQLite → PostgreSQL.
- Аккаунты и вход — `docs/specs/accounts.md`: своя небольшая модель (без ASP.NET Identity) + cookie-аутентификация, вход кодом на почту,
  регистрация по приглашениям. Сделано всё: 1 (хранилище по пользователям, перенос planner.db), 3 (приглашения, пользователи, режим Invite/Open,
  стартовый набор), 4 (аккаунт: устройства, выгрузка, удаление с «корзиной» 7 дней) и 2 (вход кодом, сессии, CSRF-заголовок
  `X-Planner` на всех изменяющих запросах, частота, почтовый ящик разработки, окно входа поверх экрана при 401 — очередь ждёт).
  Все маршруты `/api` — только после входа; открытые помечаются `AllowAnonymous` явно и вписываются в `AccountIsolationTests`
  (там же — пример запроса для каждого маршрута: новый эндпоинт без него роняет тест «А не видит данных Б»).

## 3. Экран (десктоп)

Три зоны слева направо:

### 3.1. Слева — «Роли и цели» (недельный лист Кови)
- Сверху блок **«Затачивание пилы»**: 4 измерения — тело, ум, дух, общение/эмоции; у каждого 0..n целей на неделю.
- Ниже — список **ролей** (пользовательские, редактируемые: переименовать, цвет, порядок, добавить/удалить).
  Стартовые примеры: «Я сама», «Семья», «Работа», «Дом».
- У каждой роли — 1–3 **цели на неделю** («большие камни»). Цель можно перетащить в конкретный день.
- **Цель — шаблон занятий.** У цели «раз в неделю» (1–7) и необязательные время, квадрант, длительность, заметки (окно цели — по клику).
  Перетаскивание цели в день добавляет новое **занятие** (дело-«камень» с её значениями), а не переносит; перенос занятия — перетаскиванием дела.
  Изменение цели расходится по невыполненным занятиям, кроме полей, которые у занятия «свои» (отличаются от цели: метка «своё», кнопка «как у цели»).
  Роли и квадрант у занятий всегда от цели (см. ниже про несколько ролей). Строка цели: процент справа (см. ниже); дни занятий — не под названием, а в подсказке строки «Бег · Чт · Пт · 2 из 3» и в окне цели «· дни: Чт · Пт» (`docs/specs/batch-3.md`, M2); «2 из 5» — ещё и в подсказке процента.
  Если у цели есть проект с шагами — в той же пилюле «☑ 1/3 · 25%» (шаги проекта · процент занятий).
  Процент — своей колонкой справа и не сжимает название: оно переносится по словам, «× удалить» — поверх края строки при наведении (`docs/specs/batch-3.md`, G11).
  Справа у каждой цели (и в пиле, и в ролях) — тихая пилюля-процент выполненных занятий недели: выполнено ÷ «раз в неделю», вниз до целого
  («2 раза», одно выполнено — 50%); норма выполнена (и сверх нормы) — «100% ✓» мятным; не начато — тихий пустой кружок вместо «0%» (D1).
  **Сворачивание ролей** (`docs/specs/ui-declutter.md`, U1; `docs/specs/batch-3.md`, M4): название роли — кнопка «▾/▸», сворачивает её цели (и «на неделе»,
  «дела роли на неделе»); свёрнутая — одна строка «▸ ● Работа · 2 цели», розовая точка — есть неразложенное. Заголовок раздела («Затачивание пилы», «Роли») — папка:
  сворачивает цели всех ролей раздела, названия ролей остаются видны (раздел целиком в одну строку не сворачивается). Кнопка в шапке панели —
  то же для обоих разделов. Запоминается (в браузере), по умолчанию всё развёрнуто.
  Пока тащат дело или цель, задержка над свёрнутой ролью ~0,5 с раскрывает её до броска. Счёта «1/2» у роли нет (дубль процентов целей).
  «⋯» роли — при наведении, меню «изменить роль…» · «дела роли на неделе»; «+ цель» — маленький «+» справа от названия роли (при наведении на роль,
  у роли без целей — всегда; M3).
  Цель выполнена, когда отмечено N занятий; галочка у цели отмечает ближайшее занятие (или добавляет выполненное на сегодня;
  у цели не текущей недели — выполненное занятие без дня).
  **Не больше одного занятия цели в день** (если в окне цели не включено «можно несколько раз в день»): цель, брошенная на день,
  где её занятие уже есть, ничего не создаёт — существующее занятие коротко подсвечивается, подсказка «уже есть в этот день»;
  перенести занятие в такой день тоже нельзя (остаётся на месте); галочка цели не добавляет второе занятие на сегодня
  («сегодня уже отмечено»). Уже существующие дубли не трогаются.
  Удаление цели: выполненные занятия остаются выполненными делами (без дня — встают в понедельник недели цели) и скрепками своей привычки;
  невыполненные — в корзину, мысль из ленты без дня — обратно в ленту; занятие-шаг без дня остаётся шагом у своего проекта. Проект цели и его шаги не трогаются.
- **Проект и шаги цели** (подробно — `docs/specs/tasks-steps-done.md`, P и G). В окне цели — поле «Проект [▾]» с поиском (открытые дела без родителя, «— нет»)
  и блок «Шаги цели» — шаги этого проекта: **один список шагов на цель**, общий для всех её занятий (у занятия своих шагов не бывает).
  Первое «+ шаг» у **разовой** цели без проекта создаёт проект — дело с названием цели (с ролями цели, без категории) сразу в «🛠 Проекты» — и выбирает его.
  **Привычка ≠ проект** (`docs/specs/fixes-2026-10.md`, A): у постоянной цели проект сам не создаётся никогда — только выбранный в поле «Проект»
  («Чтение» → книга); без выбранного проекта блока «Шаги» в окне постоянной цели и её занятия нет.
  Новые занятия цели становятся шагами проекта (уже существующие не трогаются); проект выполнен или в корзине — новые занятия без проекта,
  в поле пометка «(выполнен)». У постоянной цели проект — часть шаблона (с этой недели и дальше), на следующих неделях — тот же список шагов.
  Шаг из окна цели можно перетащить в день (окно на время перетаскивания бледнеет).
- **Постоянные цели («каждую неделю»).** В окне цели — переключатель «каждую неделю»: у новых целей измерений пилы включён, у обычных ролей выключен.
  У постоянной цели на каждой следующей неделе сама появляется цель с тем же шаблоном (название, раз в неделю, время, длительность, заметки,
  квадрант, роль) — без занятий, прогресс с нуля; появляется, когда неделю открывают (пропущенные недели заполняются тоже), без дублей.
  Правка шаблона постоянной цели — для этой недели и всех следующих, прошлые недели не меняются. Выключили «каждую неделю» — серия заканчивается
  после этой недели; если на следующих неделях уже есть цели — перед сохранением вопрос «Закончить «…» после этой недели? Уберутся цели: N, занятий: M»
  · «Закончить серию» · «Отмена» (`docs/specs/fixes-2026-10.md`, E1.2). Снова включили — цели следующих недель появляются заново (E1.1). Удаление постоянной цели — вопрос «Только на этой неделе» (на следующей снова появится) / «С этой недели и дальше»
  (серия заканчивается, прошлые недели остаются) / «Отмена», потом плашка «Вернуть».
  **Дни постоянной цели**: в окне цели строка «Повтор [▾]» — «сам раскладываю» (по умолчанию), «каждый день», «будни», «выходные», «свои дни»;
  под ней 7 круглых переключателей П В С Ч П С В (при «сам раскладываю» скрыты), ручное переключение кружка — «свои дни».
  Если дни выбраны: «раз в неделю» = их числу (поле заблокировано); на каждой новой неделе серии занятия сами встают в эти дни
  (время и длительность — из шаблона). Смена дней — с этой недели и дальше: на этой и уже созданных следующих неделях в выбранные
  дни без занятия добавляется занятие, невыполненные в невыбранные дни — в корзину (плашка «Убрано занятий: N · Вернуть»),
  выполненные не трогаются. Занятие можно вручную перенести на другой день — оно остаётся камнем, дни серии не меняются.
- **Несколько ролей у цели.** В окне цели роли — чипы «● Тело ×» + «+» (можно несколько, хотя бы одна: у последней «×» нет).
  Цель показывается в левой панели под каждой своей ролью — это одна и та же цель с общим прогрессом (отметили занятие — видно во всех ролях);
  в каждой роли у неё своё место в списке (новая роль — в конец). В «камнях» шапки цель считается один раз. Роли занятий = роли цели
  (на записи — точки всех ролей). У постоянной цели роли — часть шаблона: правка — с этой недели и дальше.
  Перетаскивание цели на другую роль — перенос: роль, из-под которой тащили, заменяется новой (остальные роли остаются);
  **с зажатым Shift** — роль добавляется (у призрака подпись «+ роль»). В пределах своей роли — только порядок.
  Удаление роли: цели, у которых она единственная, удаляются (как сейчас); у целей с другими ролями роль просто убирается (и из шаблона серии).
- **У дела — одна цель.** Занятие относится к одной своей цели. Сделать дело занятием цели — перетащить его на середину строки цели
  в левой панели (подсветка «сделать занятием этой цели»; у верхнего/нижнего края строки — новая цель между строками;
  мысль из ленты станет занятием без дня). Было занятием другой цели — переходит к этой (у прежней прогресс уменьшается).
  В окне дела выбора целей нет: роли и квадрант там «от цели».
  «Одно занятие цели в день»: если у цели в этот день другое невыполненное занятие — оно заменяется (в корзину, плашка «Заменено «…» · Вернуть»);
  выполненное — дело не привязывается, «уже есть в этот день». Дни постоянной цели: в день с привязанным делом новое занятие не создаётся.
- **Недособранная цель** (N1): у цели текущей или будущей недели не все занятия стоят в днях (выполненные без дня — разложены) —
  тихая подложка строки цветом акцента и тонкая полоска слева (`--unplaced-bg`, `--unplaced-bar`), подсказка «не разложено: 1 из 2».
- **Дело на дело = шаг** (N2): дело, брошенное на середину строки другого дела (в дне, в ленте, в «🛠 Проекты»), становится его шагом
  («сделать шагом «…»», плашка «„…“ теперь шаг „…“ · Вернуть»); у краёв строки — обычный порядок. Нельзя на шаг, на занятие цели, проект на дело.
- **«На неделе · N»** (N4, вариант Б; `docs/specs/fixes-2026-10.md`, B) — под целями роли: дела показанной недели без дня (`Tasks.PlannedWeek`),
  список виден сразу, если в нём есть дела (не сворачивается); невыполненное дело текущей или будущей недели подсвечено, как недособранная цель
  (подсказка «не назначено на день», `docs/specs/fixes-2026-10.md`, E2). Камнем не становятся; тащат в день, в ленту, на цель, на роль.
  Отправить: «→ на след. неделю» — последний пункт меню поля «Дата» в окне дела и мысли (`docs/specs/ui-declutter.md`, U2.5; у занятия цели — бледный,
  «у занятия цели своя неделя»), действует сразу; у дела без роли — в том же меню «в роль: …» (и «в ленту» у дела из дня); бросок дела на **заголовок роли** (в том числе после «›») — на эту неделю без дня с этой ролью
  (пока тащат — подпись «на неделе ↓»), между строками целей — по-прежнему новая цель. Плашка «„…“ → след. неделя, «Роль» · Показать · Вернуть».
  «На неделе без роли» внизу панели — только если такие дела есть (убрали роли, удалили роль). Неделя прошла — дело остаётся там.
- **«Дела роли на неделе»** — пункт «⋯» роли (`docs/specs/batch-3.md`, M3; было — строка «дела в днях · N ▸» под целями): дела показанной недели с этой ролью, кроме занятий целей;
  нет таких — пункт бледный «дел на неделе нет». Под целями — компактный список «Чт · название» с «×» (выполненные зачёркнуты), клик по делу — его окно. Раскрытие запоминается (в браузере).

### 3.2. Центр — неделя
- 7 колонок-дней (Пн–Вс), навигация «‹ › 12 — 18 октября»: стрелки рядом, подпись периода после них, фиксированной ширины
  (при листании подряд стрелки не сдвигаются; так же на экране «📊 Отчёт»), «Сегодня».
  В шапке — «камней: 2 из 8 · занятий X из Y» (занятия целей недели: отмеченные / всего по «раз в неделю»);
  подсказка при наведении: «камень выполнен, когда отмечены все его занятия».
  **Переход к дате** (`docs/specs/batch-3.md`, J): подпись недели — кнопка, G — мини-календарь под ней: месяц сеткой по неделям (наведение — вся неделя,
  клик — её неделя), «‹ месяц ›», «Сегодня», сегодня отмечено, тихие точки на днях с делами; поле «12.03 · 12.03.2027 · 12 марта · март 2027» + Enter
  (непонятное — тихая подсказка); ←→↑↓ по дням, Enter; Esc — только календарь. Только чтение: `GET /api/calendar?from=&to=` (цели серий не создаёт).
- **Сетки часов НЕТ** (решение после просмотра прототипа: по духу Кови — гибкость и приоритеты, а не расписание по часам).
  День — это просто список дел в ручном порядке. День растёт вниз вместе со списком, «+ дело» — сразу под последним делом
  (видна при наведении на день; в сегодняшнем и пустом дне, на касании — всегда; `docs/specs/ui-declutter.md`, U3-b);
  все дни недели одной высоты (по самому длинному), неделя прокручивается вертикально.
- У дела может быть **необязательное время** (реальная встреча: «15:00 Стоматолог») — показывается маленькой меткой-пилюлей на карточке.
  Дела со временем в списке дня автоматически встают по времени; дела без времени — в ручном порядке.
- У дела может быть **необязательная примерная длительность** («~30 мин») — пилюля на карточке; в заголовке дня — сумма «~3 ч».
  Расписания по ней нет — это только оценка нагрузки дня.
- **Окна — главное сразу, редкое по требованию** (`docs/specs/ui-declutter.md`, U2): поля строкой «Метка · значение»; сразу видно название,
  роль, дата и время (у цели — одна-две строки «роль · раз в неделю · каждую неделю · 🫙 копить»); редкие поля — заполненные **одной
  строкой-сводкой** («⏱ 30 мин ▸», «🛠 Ремонт ▸», «Повтор: будни ▸», «🫙 19 скрепок · 🔥2 ▸», «📝 …»; клик раскрывает именно это поле),
  пустые — строкой маленьких «+ квадрант · + длительность · + проект · + заметки» (нажали — поле появилось, фокус в нём); раскрытие не запоминается.
  У раскрытого поля справа «×» — очистить и свернуть обратно в «+ …» (`docs/specs/batch-3.md`, M1); пустое при следующем открытии — снова «+ …», заполненное — сводкой.
  Внизу — «⋯» (редкие действия: «🛠 сделать проектом», «в корзину», «удалить цель»; опасное — последним, розовым), «Отмена», «Сохранить».
  Подсказки переключателей — при наведении и строкой только после переключения. Квадрант — список «II · важно, не срочно».
  Вместо рядов чипов — поля с выпадающими списками. Роли — чипы выбранных «● Тело ×» + «+»
  (список: точка, название, галочка; закрывается кликом мимо или Esc — окно под ним остаётся); где роль «от цели» — только чипы.
  Одиночный выбор (категория мысли, роль, повтор) — поле «● Книги ▾». Время и длительность — поле «07:30» / «1 ч 30 мин» / «без»,
  по клику — барабан как в будильнике iPhone: часы | минуты (шаг 1; часы времени 0–23, длительности 0–12), колесо, перетаскивание,
  палец, ↑↓, клик по числу — ввод с клавиатуры; «без» сбрасывает. Пустое поле при открытии получает 09:00 / 30 мин.
- Задача: отметка «выполнено», редактирование по клику (название, заметки, роли, время, длительность, квадрант), цвет роли точкой/кружком-чекбоксом,
  **несколько ролей** у дела: в окне — маленькие чипы «● Тело ×» и «+» со списком ролей (множественный выбор); на записи чекбокс цвета первой роли
  (по порядку ролей), при двух ролях и больше — маленькие точки всех ролей под названием. Цель (камень) у дела по-прежнему одна,
  маленький розовый ◆ в конце названия, если дело — занятие цели недели (подсказка «занятие цели «Бег»», D2), необязательная отметка квадранта I–IV (на карточке не показывается).
  **Выполненное в дне** — внизу дня, под невыполненными (и под делами со временем), бледнее (D3); ручной порядок не меняется: сняли отметку — дело на своём месте.
- **Шаги в днях.** У дела с шагами (и у занятия цели с проектом) под названием — подпись «☑ 2/5» (только подпись); шаг в дне — с подписью «↳ Ремонт».
  У записи, которой есть что разворачивать (обрезанный текст и/или шаги), — одна стрелка «⌄» справа внизу (зона 24px): клик — текст целиком
  и список шагов под строкой, «⌃» — свернуть. Раскрытие шагов запоминается для строки (в браузере), текст после перезагрузки — снова в две строки.
  В окне дела — «+ проект» (или сводка «🛠 Ремонт ▸») и, у проекта, блок «Шаги» (см. 3.5).
- **Перенос на другую неделю.** В окне дела — поле «Дата» с меню: «сегодня», «завтра», «другая дата…» (календарь), «без даты»
  (обратно в ленту, в свою категорию или в «неразобранное»), за чертой — «→ на след. неделю». Дело встаёт в конец дел дня без времени, время и длительность сохраняются.
  Перенос на другую неделю — плашка «Перенесено на Пн 12 окт · Показать».
  Перетаскиванием: пока тащат дело, по краям недели проступают широкие полупрозрачные зоны «‹ прошлая неделя» / «следующая неделя ›»
  (на всю высоту, в цветах темы; бросить дело у края понедельника/воскресенья можно сквозь них). Задержать над зоной или над стрелкой
  «‹ ›» в шапке ~0,5 с — неделя перелистывается (держишь дальше — листается дальше),
  дело можно бросить в любой день новой недели; Esc или бросок мимо — неделя возвращается. Цели так не листаются — они привязаны к своей неделе.
  Занятие цели («камень») при переносе на другую неделю остаётся камнем: становится занятием той же цели на той неделе (цели её серии),
  а если её там нет — там создаётся эта цель (1 раз в неделю, тот же шаблон, без повтора). У прежней цели прогресс уменьшается.
- «Сегодня» обновляется само: в полночь и когда окно снова активно; если наступила новая неделя, а на экране текущая — переключается на новую.
- **Шапка недели** — только «📈 Итоги» и «⚙ Настройки» (линейные значки, подпись при наведении; `docs/specs/batch-ux.md`, BI1).
  «📈 Итоги» — один экран с вкладками «Привычки» (по умолчанию) · «Выполненное» · «Отчёт», вкладка запоминается (BI2).
  «⚙ Настройки» — тема оформления, срок «давно лежат» (BS2), «✦ Моя миссия» и её блок в панели (BM), «Как это устроено» (словарь, схема, пояснения, клавиши; BG3).
  **«Моя миссия»** (BM): экран поверх недели — свободный текст (до 5000 знаков, переносы сохраняются; пустой — «Начни с конца: кем ты хочешь быть?»)
  и у каждой роли строка «кем я хочу быть в этой роли» (до 200 знаков); сохраняется по уходу из поля, без плашки. Строка роли — в подсказке
  названия роли и в окне роли; по настройке — свёрнутый блок «✦ Моя миссия ▸» вверху левой панели (раскрытие запоминается); шаг 4 недельного обзора.
  **Словарь** (BG1): мысль, дело, проект, шаг, цель недели (= камень), занятие (◆), привычка, скрепка — одни и те же слова везде;
  дело в корзине — плашка «„…“ в корзине · Вернуть» (цель, роль, категория — «Удалено «…»»). Кови и «7 навыков» в интерфейсе не упоминаются.
- **Недельный обзор** (`docs/specs/batch-ux.md`, BR): кнопка «🗓 Недельный обзор» в шапке «Итогов», клавиша W; в воскресенье после 12:00
  (пропустили — в понедельник до 12:00) один раз плашка «Неделя заканчивается · Недельный обзор». Экран поверх недели, шаги 1–5 («Назад» / «Дальше», Esc):
  1 «Не сделано» — дела недели по дням и «на неделе»: «на след. неделю» (без роли — «в роль: …») / «в ленту» / «в корзину» / «оставить»;
  камни — у разовой цели ещё и «на след. неделю» (к той же цели на той неделе), у постоянной — только «в корзину» / «оставить»; «Отложить всё»;
  2 «Привычки» (скрепок из нормы, 🔥, ⚠ «не пропускай дважды»); 3 «Давно лежат»; 4 «Миссия» (текст и строки ролей, «изменить»); 5 «Камни» — следующая неделя на экране,
  цели по ролям, «у роли «Дом» нет камней», «+ цель»; «Готово» — следующая неделя. Обзор — по текущей неделе (в понедельник до 12:00 — по прошлой).
  Ничего нового не хранится: каждое действие — обычное, со своей плашкой и «Вернуть».
- **«📊 Отчёт»** — вкладка «Итогов» (подробно — `docs/specs/next-batch.md`, N5): экран поверх недели, только чтение.
  Период — одно поле «месяц ▾»: неделя (показанная), месяц (по умолчанию текущий), N месяцев (2–12), год, свой; стрелки листают. Неделя входит в период по своему четвергу.
  Привычки и постоянные цели: план (сумма «раз в неделю» целей серии за недели периода) / факт (скрепки, и удалённых целей тоже) / %, 🔥/⚠ на конец периода;
  разовые цели одной строкой «камней N, выполнено M»; «Выполненное» по категориям (по дню отметки). «Скачать CSV» — UTF-8 с BOM, «;», CRLF, ДД.ММ.ГГГГ.
  API: `GET /api/report?from=&to=`, `GET /api/report.csv?from=&to=`.
  **«Список ⇄ Дашборд»** (`docs/specs/batch-ux.md`, BD; вид запоминается в браузере): тот же период; привычки — тепловая карта (недели × Пн…Вс,
  0/1/2/3+ скрепок, каникулы штриховкой, «все привычки ▾» / одна; всего скрепок, 🔥 сейчас и лучшая серия — `BestWeekStreak`),
  «колесо» пилы (выполненные занятия по измерениям), баланс ролей (выполненные дела по дню отметки; пила сверху, «без роли» внизу),
  доля II квадранта по неделям (среди дел с квадрантом, подсказка «без квадранта: N»), «давно лежат» (мысли старше срока, 5 самых старых).
  Графики свои (SVG/CSS), у каждого подсказки и текст для диктора. API: `GET /api/dashboard?from=&to=`.

### 3.3. Справа — лента «Когда-нибудь» (узкая полоса, ~260–300px)
- **Никаких сроков и дат** в ленте. Это склад мыслей: может сделаю на следующей неделе, может через 10 лет, может передумаю.
- **Категории** — ОДИН уровень (без подкатегорий). Категории ленты — НЕ то же самое, что роли Кови (роли = «кто я», категории = «о чём дело»).
- **«Неразобранное»**: мысли можно записывать без категории. Они копятся сверху ленты, над категориями, без заголовка-папки —
  с тихой подписью «неразобранное» и счётчиком; пустое не видно (во время перетаскивания — место, куда бросить, поверх поля
  «Записать мысль», без сдвига ленты). Перетаскивание из «неразобранного» в категорию и обратно — как между категориями.
  Это не категория (в модели — дело ленты с CategoryId = null), переименовать или удалить его нельзя.
- Вид — **аккордеон**: заголовок категории с серым счётчиком дел; клик раскрывает/сворачивает. Раскрыто может быть **сколько угодно** категорий одновременно; состояние раскрытия запоминается.
- Вся лента — одна прокручиваемая колонка: колесо мыши листает и внутри раскрытых категорий, и по всем категориям подряд.
- Сверху — **поиск** (фильтрует по всем категориям, раскрывая совпадения).
- В конце каждой раскрытой категории — строка «+ добавить» (видна при наведении на категорию; на касании — всегда): ввод текста + Enter, без форм. Новое дело — в конец категории (а из «Записать мысль» сверху ленты — наверх).
- Рядом с поиском — «⋯»: «+ категория наверх» (новая встаёт в начало) и «свернуть / развернуть всё» (`docs/specs/ui-declutter.md`, U3); внизу — «+ категория» (в конец).
- Сверху ленты — быстрое поле «Записать мысль…» + выбор категории значком (эмодзи категории, у «неразобранного» — 📥, без эмодзи — короткое название; D8): по умолчанию — «неразобранное»; выбранная категория держится до перезагрузки.
- У категории может быть эмодзи-иконка (необязательно).
- Поле «Записать мысль» есть всегда; если категорий ещё нет — под ним подсказка «создайте первую категорию».
- Дело, созданное прямо в плане, категории не имеет, пока лежит в плане. При возврате в ленту: перетаскиванием — туда, куда бросили;
  другим способом (обзор недели, восстановление из корзины, удаление цели или роли) — в исходную категорию, а если её нет — в «неразобранное» (без вопросов).
- Удаление категории: пустая удаляется сразу; непустая — вопрос «Удалить „Название“? В ней N дел» с кнопками
  «Переложить в неразобранное» (дела наверх «неразобранного», в том же порядке) / «Удалить вместе с делами» (дела — в корзину) / «Отмена».
  Дела этой категории, лежащие в плане или выполненные, теряют категорию: вернутся в ленту — в «неразобранное», в «Выполненном» — в группе «без категории».
- Порядок дел внутри категории — ручной (drag). Дела можно перетаскивать между категориями.
- Клик по мысли — окно: название, категория, «Дата: в ленте ▾» (сегодня/завтра/другая дата — мысль встаёт в день; «→ на след. неделю»),
  кнопка «🛠 Сделать проектом» с подписью «добавить шаги и раскладывать их по дням» (у мысли нет «+ шаг»), «+ заметки · + проект».
- **Проекты в ленте не живут** (лента — только мысли): они в «🛠 Проекты» (см. 3.5). Поиск ленты ищет мысли; совпавшие проекты —
  тихой строкой «🛠 в проектах: N» (клик — панель проектов с тем же поиском).
- **Отметка в ленте.** У каждой мысли — квадратный чекбокс (нейтральный бирюзовый). Отметили — мысль уходит из ленты в «Выполненное»,
  у значка корзины плашка 6 с «„…“ выполнено · в корзину · вернуть» («вернуть» — на прежнее место).
  Шаг, брошенный в ленту (из дня), — снова мысль («больше не шаг · Вернуть»).
- **«✓ Выполненное»** — вкладка «📈 Итоги» (`docs/specs/batch-ux.md`, BI2); экран поверх недели (Esc/крестик): выполненные дела, которые
  хоть раз были в ленте (отмеченные в ленте или в дне; не шаги, не дела, созданные прямо в неделе), по их категориям, «без категории» — в конце;
  в заголовке группы — счёт по годам, свежие сверху. Строка: чекбокс (снять — дело в ленту на своё место или открытым в свой день), название (окно дела),
  «14 шагов · 5 недель · 12 занятий» (раскрывает шаги), дата отметки. Удаление — из окна дела.
- Длинные записи в ленте и в днях — не больше 2 строк, с «…». Полный текст — во всплывающей подсказке
  (навести и задержать ~0,5 с; только если текст обрезан), стрелкой «⌄» прямо в строке (не запоминается) и в окне по клику.
- Внизу — «+ категория».
- **Давно лежат** (`docs/specs/batch-ux.md`, BS): возраст мысли — от последнего изменения по существу (`Tasks.UpdatedAt`: название, заметки,
  категория, проект/шаг, состояние; порядок перетаскиванием — нет). Срок — «⚙ Настройки» (1 / 3 / 6 / 12 мес или своё 1–36; на сервере, `AppSettings`).
  Старше срока (от max(UpdatedAt, KeptAt)) — розовое «4 мес» справа в строке; подсказка «лежит 2 мес · с 14 авг» — у всех мыслей.
  При загрузке и в полночь — плашка о перешагнувших срок: одна — «„…“ лежит уже 3 мес · Посмотреть · Оставить», несколько —
  «5 мыслей лежат больше 3 мес · Посмотреть»; о каждой — один раз за перешагивание (`StaleNotifiedAt`). «Посмотреть» — лента «давно лежат»
  (самые давние сверху, крестик — обычная лента); «Оставить» — `KeptAt`, свежая на один срок.
  API: `GET/PUT /api/settings`, `POST /api/tasks/{id}/keep`, `POST /api/thoughts/stale-notices`.
- **Корзина**: маленькая серая иконка в самом низу ленты, без яркого счётчика, не отвлекает. Клик — небольшое всплывающее окно со списком удалённого: «вернуть» / «удалить навсегда» (значки при наведении на строку, на касании — всегда; удаление — с подтверждением в строке) / «очистить всё». Хранится бессрочно, чистится только вручную.
- **Защита от случайного удаления.** Крестиков удаления в строках ленты нет: удаляют из окна («в корзину») или перетаскиванием записи
  (дело, мысль, цель) на значок корзины — при наведении он подсвечивается. После любого удаления (дело, мысль, цель, роль, категория, очистка корзины)
  на 6 секунд плашка «Удалено «…» · Вернуть» — как и все плашки, вверху по центру под шапкой недели (D7); «Вернуть» отменяет полностью. Устроено так: экран меняется сразу, а на сервер удаление уходит
  через 6 секунд — или раньше, перед любым другим изменением или когда окно уходит в фон (тогда «Вернуть» уже не предлагается).
  Исключение — «удалить навсегда» в корзине: там подтверждение, без плашки.
  **В днях** — ещё и серая 🗑 справа при наведении на дело (поверх края записи, текст и пилюли не сдвигает); на касании свайп влево
  показывает 🗑, касание мимо прячет (долгое нажатие — по-прежнему перетаскивание). Без подтверждения: дело в корзину, та же плашка,
  значок корзины коротко «вздрагивает» (при любом удалении в корзину). Долгое или «дёрнувшееся» нажатие на 🗑 — не клик (правило кликов dnd.js).

### 3.4. Привычки — банки со скрепками («Атомные привычки»)

Макет и **все правила подсчёта** — `docs/habits-mockup.html` (блок «правила (для ТЗ)» обязателен); как есть — `docs/specs/habits.md`.
- **Привычка = постоянная цель с «🫙 копить».** Любая серия целей с «каждую неделю» и включённым «🫙 копить» — привычка с банкой;
  отдельной сущности «копилка» нет. Переключатель «🫙 копить» — в окне цели, виден только при «каждую неделю»; когда «каждую неделю» включают,
  он предустанавливается: есть роль-измерение пилы — включён, иначе выключен (видно до «Сохранить»). Смена ролей «копить» не меняет.
  «Копить» — свойство серии целиком: включили — считается вся история. Выключили — привычка пропадает с экрана 🫙 (не архив), банка сохраняется.
  Разовые цели копить нельзя. Создать привычку — постоянная цель в пиле (или «копить» у постоянной цели любой роли).
- **Скрепка** — выполненное занятие цели этой серии (корзина не считается; занятие-шаг проекта — тоже скрепка). Занятие без дня
  (отмечено галочкой цели другой недели) — скрепка понедельника недели цели. Удалили цель — её выполненные занятия остаются скрепками серии
  (`ClipSeriesId`); удалили серию целиком (последнюю роль) — скрепки уходят вместе с привычкой. Всего = стартовое число + скрепки;
  **вычисляется, не хранится**: сняли галочку — скрепка ушла. Полных банок = всего ÷ размер банки (по умолчанию 30), в текущей — остаток.
- **Норма недели — «раз в неделю» цели той недели.** Правка цели (норма, дни, время, роли) «с этой недели и дальше» прошлые недели
  не меняет: они оцениваются по своей тогдашней норме — у привычки одна непрерывная история (серия при правке не делится).
  Неделя без цели (удалили «только на этой неделе», серия закончилась) — без нормы: не засчитана и не пропуск.
- Неделя засчитана, если скрепок ≥ нормы. Текущая неделя «в процессе» и серию не ломает, но как только её норма выполнена — сразу входит
  в серию и снимает паузу (награда мгновенно); месяц — только по окончании. Серия недель 🔥: первый пропуск — ⚠ пауза
  («не пропускай дважды»), второй подряд — обрыв (пауза перед ним показывается пропуском). Недели до первой недели серии не считаются
  (первая неделя — самая ранняя из начала серии и недель её целей: цель из переноса занятия может быть раньше);
  первая неделя без нормы — не пропуск. Месяц — по четвергу недели; засчитан, если в нём серия недель не прервалась; серия месяцев 🌙 — так же.
- **Каникулы** (с — по, все привычки или выбранные): неделя с ≥ 4 днями каникул — не засчитана и не пропуск, серия замирает;
  месяц из одних каникул — каникулы. Скрепки в каникулы идут в общий счёт.
- **Архив.** Сняли «каждую неделю» (или удалили цель «с этой недели и дальше») — привычка уходит в архив экрана 🫙 со всей историей;
  снова включили — история продолжается (с «копить» по правилу выше). Законченные серии без скрепок и с банкой по умолчанию в архиве не показываются.
- Экран привычек — вкладка «📈 Итоги · Привычки» (BI2): карточки сгруппированы по 4 измерениям пилы, затем обычные роли (привычка в нескольких ролях — один раз,
  в группе первой роли — сначала измерения пилы, потом обычные роли, — остальные — маленькими чипами на карточке); на карточке — банка, счёт, полка, 🔥/🌙/⚠,
  «эта неделя» точками, 26 недель (в подсказке — норма той недели), 7 месяцев, среднее, месяц, год; «+1 сегодня» и значок ⚙ «настроить»
  в углу карточки (при наведении; стартовое число, размер банки). Внизу — свёрнутый архив; «удалить» — только у привычки из архива: плашка «Удалено … · Вернуть»
  на 6 с, удаление на сервере отложенное. **Удаление привычки не удаляет цель и её дела** — только счёт (стартовое число, размер банки,
  каникулы этой привычки) и выключает «копить»; снова включили «каждую неделю» — привычка вернётся с банкой по умолчанию. Там же «🏖 Каникулы».
- **«+1 сегодня»** — занятие цели этой недели на сегодня, отмеченное: есть невыполненное сегодняшнее — отмечается, иначе новое встаёт в конец
  дня. «Одно занятие в день» — как у галочки цели: сегодня уже отмечено — «сегодня уже отмечено».
- В левой панели у цели-привычки пилюли банки нет (там процент недели). В окне такой цели — строка
  «🫙 привычка: 102 скрепки · 🔥13» (клик — экран 🫙) и настройки банки: стартовое число, размер. В окне дела ничего про привычки нет.
  Отметили занятие привычки — внизу на пару секунд «📎 +1 в «Бег» · 103 · неделя 3 из 3 ✓».
- Логика — `Planner.Core/Habits/HabitStatsCalculator` (чистая функция, unit-тесты на все крайние случаи) и `Services/HabitService`.
  API: `GET /api/habits` (только чтение, вся статистика одним запросом по занятиям), `PUT /api/habits/{id}` (банка),
  `DELETE /api/habits/{id}` (только из архива), `POST /api/habits/{id}/plus-one`, `/api/vacations`. Id привычки — id серии.

### 3.5. Шаги и проекты

Все правила — `docs/specs/tasks-steps-done.md` (S, G, R) и `docs/specs/next-batch.md` (N6 «🛠 Проекты»). Кратко:
- **Шаг** — дело с ParentId (один уровень: у шага нет шагов, родитель не бывает шагом); **проект** — дело с флагом IsProject
  (отдельной сущности нет). Шаг — полноценное дело: может стоять в дне, иметь время, роли, быть занятием цели. В ленте отдельной строкой не бывает.
- **Проектом дело становится явно**: «🛠 Сделать проектом» в окне мысли, «⋯ → 🛠 сделать проектом» в окне дела (шаги — только у проекта,
  `docs/specs/batch-ux.md`, BP2–BP3), выбор в поле «Проект» цели, проект цели из «+ шаг» в окне разовой цели;
  плашка у мысли — «Теперь в «Проектах» · Показать · Вернуть», у дела — «„…“ теперь проект · Показать · Вернуть». 🛠 у проекта везде:
  в дне, «↳ 🛠 Ремонт» у шага, в списке поля «Проект».
  Все шаги удалили — дело остаётся проектом; «🛠 больше не проект» — только у проекта без шагов (мысль — обратно в ленту на своё место).
  Шаг и занятие цели проектом не бывают.
- **«🛠 Проекты»** — вкладка над правой колонкой «Мысли · N | Проекты · N» (`docs/specs/batch-ux.md`, BP1; вкладка запоминается в браузере).
  Пустая вкладка объясняет: «Проект — дело из нескольких шагов, например «Ремонт» или книга. Шаги можно раскладывать по дням.»
  Все открытые проекты (из ленты и из плана любой недели): группы по категориям в порядке ленты, «без категории» в конце; фильтр
  «все категории ▾»; свой поиск (по названию и шагам); «+ проект» (в категорию фильтра). Строка — как в ленте: чекбокс, «🛠 ☑ 2/5»,
  «⌄» — шаги с «+ шаг», метка дня у проекта в плане, клик — окно. Проект тащат в день, из дня — в группу (снять с дня, в эту категорию);
  шаги — в дни, как из ленты. Ручного порядка в панели нет.
- **Проект в дне** — маленькая 🛠 перед «☑ 2/5» и тонкая полоска прогресса внизу строки (у занятия цели с проектом цели — нет).
- Шагом дело становится только явно: поле **«Проект [▾]»** в окне любого дела (с поиском, **только проекты**; «— нет» — убрать из проекта:
  без дня — обратно в ленту, в дне — остаётся в дне). У проекта поле неактивно («это проект — проект не бывает шагом»).
  В окне шага — «↳ Ремонт» (клик — окно проекта).
- В окне проекта — блок «Шаги ☑ N/M»: добавить (Enter), отметить, переименовать, порядок перетаскиванием, метка дня («Чт 12 окт»), клик — окно шага,
  🗑 при наведении — в корзину с «Вернуть»; занятия цели, которые шаги проекта, — отдельной строкой «N занятий ▸» (в «☑ N/M» не входят).
- Шаг перетаскивают как любое дело: из раскрытого списка или окна — в день, на другую неделю, на строку цели; брошенный на строку своего проекта
  или в его список — снимается с дня; в ленту в другое место — снова мысль.
- **Автоотметка:** отметили шаг, и все шаги проекта (без занятий) выполнены — проект отмечается сам (плашка «„…“ выполнен → в «Выполненном» · Показать · Вернуть», BP5);
  отметили из занятия цели — отмечается и это занятие. Больше ничего само не меняется: снятие шага, новый шаг, отметка проекта шаги и проект не трогают.
- Проект в корзину — с его шагами (кроме занятий: они отвязываются и остаются скрепками); «Вернуть» и возврат из корзины — вместе. Шаг в корзине — «↳ Ремонт».
- API: `GET/POST /api/tasks/{id}/steps`, `PUT /api/steps/{id}`, `PUT /api/steps/{id}/done`, `PUT /api/tasks/{id}/parent`, `PUT /api/tasks/{id}/project`,
  `POST /api/goals/{id}/steps`, `GET /api/done`; открытые проекты плана — в `GET /api/board` (`PlannedProjects`);
  шаг удаляется как дело (`DELETE /api/tasks/{id}`).

### 3.6. Горячие клавиши и быстрый поиск (`docs/specs/batch-ux.md`, BK)

- N — «Записать мысль…» (вкладка «Мысли», колонка раскрыта), D — «+ дело» сегодня, ← / → — неделя, T — к сегодня, G — перейти к дате, H — «Итоги»,
  ? — «Как это устроено», P — «Мысли ⇄ Проекты», W — недельный обзор, Ctrl+K или / — быстрый поиск, Ctrl+Z — «Вернуть» на плашке (вне поля ввода), Ctrl+Enter, Esc.
  Клавиши — физические (в русской раскладке N = «т»). Без Ctrl — не при наборе текста и не при открытом окне, экране, списке, перетаскивании;
  с Alt/Meta не перехватываются. Одна точка — `wwwroot/js/hotkeys.js` + сервис `Hotkeys`. Подсказка клавиши — в `title` кнопок.
- **Быстрый поиск** — окно по центру сверху: «Дела · Мысли · Проекты · Цели» (до 8 в группе, название и заметки, «ё» = «е», корзина не ищется;
  дела — с датой, выполненные зачёркнуты). ↑↓, Enter: дело — его неделя и окно, мысль — «Мысли» и окно, проект — «Проекты» и окно, цель — её неделя и окно.
  Набрана дата («12 окт», «12.03», «март 2027») — первым пунктом «перейти к неделе 12 — 18 октября».
  API: `GET /api/search?q=`.

## 4. Перетаскивание (ключевая фича)

- Лента → день, лента → цели роли.
- План → обратно в ленту (задача снова без даты, в своей исходной категории).
- Внутри плана: между днями и внутри дня (порядок); на другую неделю — задержать дело над краем недели или стрелкой «‹ ›» в шапке.
- Внутри ленты: переупорядочивание и перенос между категориями.
- Реализация на **pointer events** (не HTML5 DnD — он плохо работает на iOS Safari): мышь — сразу, палец — после долгого нажатия (~300 мс). Призрак карточки, подсветка зоны сброса, автоскролл ленты и недели у краёв.
- Изменения сохраняются на сервер сразу (оптимистичное обновление UI).
- **Нет связи** (`docs/specs/batch-ux.md`, BN): изменения уходят на сервер по одному и по порядку (`ConnectionQueue` в `PlannerApi`);
  не дошедшее из-за связи остаётся на экране и ждёт — следующие встают за ним. Плашка вверху (цвет `--warn`, сама не исчезает):
  «Нет связи — изменения не сохранены (3), повторю попытку · Повторить сейчас»; повтор через 2, 5, 10, 30 с, дальше каждые 30 с,
  сразу — по событию online и при возврате в окно. Дошло — «Связь восстановлена — сохранено 3», экран перечитан. Ответ сервера с ошибкой —
  как раньше (сообщение, перечитать). Чтения ждут, пока очередь уйдёт. Закрыть вкладку с несохранённым — браузер спрашивает.
  Очередь между перезагрузками не хранится.

## 5. Модель данных

- `User` (в `accounts.db`) — Id (GUID — им же назван файл данных), Email (нижний регистр, уникальна), IsAdmin, CreatedAt, LastLoginAt?.
  Всё ниже — в файле данных пользователя (`users\<Id>.db`), без UserId: чужих строк в открытой базе нет.

- `Task` — Id, Title, Notes?, CategoryId? (для ленты; у дела ленты null — «неразобранное»; категорию дело помнит и в плане — для возврата), роли (0..n, таблица TaskRoles: TaskId + RoleId), Quadrant? (1–4), цель (0..1, таблица TaskGoals: TaskId + GoalId + Position — всегда 0),
  State: Someday | Planned | Done | Trashed,
  PlannedDate? (DateOnly), StartTime? (TimeOnly — необязательная метка времени, без сетки),
  DurationMinutes? (примерная длительность, 1–1440),
  SortOrder, CreatedAt, CompletedAt?, TrashedAt?, PreviousState (для возврата из корзины),
  ParentId? (шаг; один уровень), StepOrder (место в списке шагов), IsProject (проект: явно сделан проектом; есть шаги ⇒ true),
  IsFromSomeday (хоть раз лежало в ленте — для «Выполненного»),
  ClipSeriesId? (выполненное занятие удалённой цели — скрепка этой серии), PlannedWeek? (на неделе без дня — понедельник; только без PlannedDate, не у занятий),
  UpdatedAt (последнее изменение по существу — ставит хранилище при сохранении), KeptAt? («Оставить»), StaleNotifiedAt? (плашку «давно лежит» показали).
- `AppSettings` — одна строка: StaleMonths (3), Mission? (≤ 5000), ShowMissionInPanel (false).
- `Category` — Id, Name, Emoji?, SortOrder, IsExpanded. Без IsSystem/«Входящих».
- `Role` — Id, Name, Color, SortOrder, SawDimension? (Body | Mind | Spirit | Social — 4 измерения пилы; у обычных ролей null), Vision? («кем я хочу быть», ≤ 200).
- `WeeklyGoal` — Id, роли (1..n, таблица GoalRoles: GoalId + RoleId + SortOrder — место цели в списке этой роли), WeekStart (DateOnly, понедельник), Title, TimesPerWeek (1–7),
  шаблон занятий: StartTime?, Quadrant?, Notes?, DurationMinutes?, ProjectId? (проект: новые занятия — его шаги, его шаги — шаги цели).
  Занятия — дела, связанные с целью через TaskGoals (много на одну цель; у дела — одна цель); занятия в корзине не считаются.
  «Выполнено» не хранится: цель выполнена, когда занятий в состоянии Done не меньше TimesPerWeek.
  Поле занятия «своё», если его значение отличается от значения цели (отдельных флагов нет).
- `GoalSeries` — «та же цель» на разных неделях: роли (таблица GoalSeriesRoles: SeriesId + RoleId), шаблон (Title, TimesPerWeek, StartTime?, Quadrant?, Notes?, DurationMinutes?, ProjectId?),
  IsRecurring («каждую неделю»), FirstWeek, LastWeek? (null — без конца), GeneratedThrough (до какой недели цели уже созданы — поэтому удалённая
  «только на этой неделе» цель сама не возвращается). У `WeeklyGoal` — SeriesId? (уникально вместе с WeekStart). Цели постоянной серии создаются
  лениво — при открытии недели (GET /api/week). Непостоянная серия только связывает цели, между которыми переносили занятия.
- У цели и серии — AllowSeveralPerDay («можно несколько раз в день», по умолчанию false) — часть шаблона.
- У цели и серии — Days? (дни недели, битовая маска Пн = 1 … Вс = 64; null — «сам раскладываю») — часть шаблона; при выбранных днях TimesPerWeek = их числу.
- У серии — IsHabit («🫙 копить») и банка привычки: JarSize (30), StartCount (0).
  Привычка — не сущность, а постоянная серия с IsHabit; архив — серия закончилась (LastWeek задан).
  `Vacation` — Id, From, To, привычки (таблица VacationHabits: VacationId + HabitId — id серии; пусто — все).
- Задача, вынесенная из ленты в план, — это та же сущность (меняется State/PlannedDate), а не копия; при возврате в ленту возвращается в свою категорию
  (и перестаёт быть занятием цели).

## 6. Мобильная раскладка (этап 2, но не ломать заранее)

- Узкий экран: один день (свайп между днями) или неделя списком; роли и цели — отдельной вкладкой.
- Лента — выезжающая шторка сбоку; перетаскивание из шторки в день.

## 7. Этапы

1. **MVP**: каркас решения, БД, API, десктопный экран (роли/цели, неделя из 7 дней-списков, лента с категориями, поиском, корзиной), перетаскивание, сохранение.
2. **Недельный обзор**: в конце недели — экран с невыполненным; по каждому: перенести / вернуть в ленту / удалить; там же выбор «больших камней» на следующую неделю.
3. PWA + мобильная раскладка + проверка на iPhone.
4. Повторяющиеся дела, квадранты I–IV со статистикой за неделю, архив выполненного.
   **Подзадачи**: дело-чеклист; подзадача может засчитываться в свою цель; дело выполнено, когда отмечены все подзадачи
   (пример: «Прогулка в парке» → «10к шагов» (Тело) + «посидеть на лавочке в тишине» (Дух)).
   Сделано раньше (docs/specs/tasks-steps-done.md): шаги и проекты (3.5) — шаг может быть занятием цели, проект отмечается сам по шагам;
   архив выполненного — экран «Выполненное» (3.3).
5. (Опционально) доступ с телефона через Tailscale, Docker-образ, Identity.

- Названия дней — бирюзовые (`--b-deep`), розовым только сегодняшний день. Hover у записей — мятный.
- Три зоны — полупрозрачные плавающие панели со скруглением ~22px, без рамок.
  Левая (роли) — самая светлая и прозрачная (едва заметный шалфей + blur); правая (лента) — чуть мятная.
- Дни — «страницы в точку»: фон с точечной сеткой бирюзового оттенка, скругление ~18px.
  Сегодня — заметно, но мягко: подложка цвета акцента (≈20%) и обводка 2px (переменные темы --today-bg / --today-ring;
  проверка в themes-contrast: обводка от 2:1 к обычному дню), бейдж «сегодня» пастельный; выходные — едва заметный бирюзовый оттенок (≈5%). Никаких резких контрастных выделений.
- **Кнопки — явные, одной системой** (`docs/specs/fixes-2026-10.md`, D; CSS-переменные `--btn-*` во всех темах): главная («Сохранить») — залитая мятная `.btn.primary`;
  обычная («Отмена», «свернуть всё», входы в экраны) — светлая пилюля с тонкой обводкой `.btn`; добавить («+ дело», «+ шаг», «+ категория») — пунктирная `.add`;
  опасная («в корзину», «удалить цель») — мягкая розовая `.btn.danger`; действия на плашках — маленькие пилюли; значки в шапке — круглые `.icon-b`.
  Зона нажатия ≥ 24px, заметное наведение, фокус с клавиатуры — кольцо `--focus-ring`. Серое слово-кнопка — не делаем.
- Записи — строки, НЕ карточки: квадратный чекбокс цвета роли (зона нажатия — вся левая полоса записи, ~30px), текст, пилюли «время» (бирюзовая) и «камень» (розовая). При наведении — лёгкая розовая подложка.
- Шрифты: **Nunito** — основной; **Caveat** (рукописный) — названия дней недели; **Lora** — заголовки панелей и недели.
- Палитра «Лотос»: текст `#3e4d52`, приглушённый `#657579`, бледный `#828f92`, линии `#efe6e7`;
  розовый — **«Зефир»** — самый светлый, чистый и воздушный, без серости и без коралла: `#f9d0e0` / мягкий `#fff5f9` / глубокий `#c4769a` / текстовый `#a5587c`; бирюза `#9fd6c9` / `#e8f6f2` / `#327b6e`.
  (Глубокие и текстовые оттенки подняты до порогов контраста, см. 8.1.)
- Цвета ролей — 18 пастельных оттенков одинаковой светлоты и мягкости, прохладных; не только розовый и зелёный (образец — `docs/role-palette.html`):
  `#9fd3bd` `#6fbfae` `#8ac2c4` `#b9d3b0` `#cfe3a8` `#f3e3a6` `#a9cde8` `#8fb4e3` `#b7c4f0` `#c9b8ec` `#dcb8e6` `#e8c1dc` `#f9d0e0` `#f2b3c6` `#f6c6b8` `#94b4b5` `#b8c2cc` `#c9c1d6`.
  Стартовые: Тело `#9fd3bd`, Ум `#a9cde8`, Дух `#c9b8ec`, Общение `#f9d0e0`, Я сама `#dcb8e6`, Семья `#b9d3b0`, Работа `#8fb4e3`, Дом `#f3e3a6`.
- Иконки категорий — эмодзи. Минимум линий, больше воздуха.

- Переключатель — в окне «⚙ Настройки» (`docs/specs/batch-ux.md`, BI5): список с мини-превью каждой темы, выбор применяется сразу.
- Выбор запоминается (сейчас — в браузере; когда появятся аккаунты — в профиле пользователя).
- Шрифты тем — локально в `wwwroot/fonts` (OFL), грузятся только для выбранной темы.
- Декор (веточка, дюны) — только в свободной нижней части ленты, не перекрывает записи.
  «Пять колец» — inline SVG (`GorinDecor`): ветви и дым — блоком в конце прокручиваемой части панели, облако, солнце и лепестки — под текстом;
  `pointer-events: none`; уже 900 px или ниже 640 px — декора нет.
- Без логотипов, названий и узнаваемых элементов игр — только настроение.
- Цвета ролей общие для всех тем; в тёмных темах (obsidian, neon) проверить читаемость.
- Контраст (сценарий tests/e2e/themes-contrast.mjs): тёмные темы — весь текст WCAG AA; светлые — основной текст AA (4.5:1, крупный 3:1),
  второстепенный («+ цель», «+ дело», «ещё дела», счётчики, выполненные дела, подсказки) — не ниже 3:1. Поднимать ровно до порога, нежность сохранять.
  Переменные: `--soft` — AA, `--faint` — 3:1, `--b-deep` — AA, `--a-deep` — 3:1 (крупное и значки), `--a-ink` — мелкий розовый текст, AA.

## 9. Правила работы

- git с первого шага, небольшие осмысленные коммиты.
- Перед каждым «готово» — `dotnet build` без ошибок и `dotnet test` зелёный.
- Проверять UI в браузере (`dotnet run --project Planner.Server`), особенно перетаскивание.
- Не добавлять платные сервисы и внешние облачные зависимости.
- Комментарии и UI — на русском; идентификаторы в коде — на английском.
- README с инструкцией: как запустить, где лежит файл БД, как сделать бэкап.
- Python на этом компьютере не установлен — для служебных скриптов используй PowerShell, dotnet или node.
