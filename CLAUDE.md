# CoveyPlanner — ТЗ и правила проекта

Личный планировщик по мотивам недельного листа Стивена Кови («7 навыков высокоэффективных людей», глава 3 «Главное — вперёд»)
плюс лента дел «когда-нибудь», из которой задачи перетаскиваются в план.

Владелец — Анна, C#-разработчик. Код должен быть понятным, идиоматичным C#, чтобы его было легко дорабатывать руками.

---

## Принципы модели

1. **У каждой сущности один смысл.** Цель — цель, категория ленты — папка, привычка — постоянная цель пилы.
2. **Никаких автоматических связей** (по категории, по названию и т.п.): что с чем связано, решает только явное действие.
3. **Ничего не превращается во что-то другое переключателем** (не бывает «вида», меняющего смысл сущности).
4. **Переход — только явным действием, и вещь переезжает целиком**, а не живёт в двух местах (мысль из ленты → дело в плане — та же
   сущность; удалили привычку — её цель и дела не трогаются).

---

## 1. Цели и ограничения

- Сейчас: пользоваться с компьютера через браузер (сервер крутится локально).
- Потом: iPhone (PWA, «На экран Домой») и веб. Нативное iOS-приложение НЕ делаем.
- Ничего платного. Никаких сторонних облаков/BaaS (Supabase, Firebase и т.п.) — приложение независимое, данные у владельца.
- Путь роста: localhost → телефон через Tailscale/ZeroTier к домашнему ПК → (опционально) VPS/Docker. Код при этом не меняется.

## 2. Стек

- .NET 10 (LTS).
- `Planner.Server` — ASP.NET Core Web API (minimal API или контроллеры), EF Core + SQLite (один файл БД), миграции EF.
  Сервер также хостит клиент (Blazor WASM hosted).
- `Planner.Client` — Blazor WebAssembly, PWA (manifest + service worker), интерфейс на Razor/C#. JS — только точечно через JS interop, если без него никак.
- `Planner.Shared` — DTO и контракты API.
- `Planner.Core` — доменная модель и логика (без зависимостей от ASP.NET / EF).
- `Planner.Tests` — xUnit, тесты на доменную логику и API (WebApplicationFactory).
- UI-библиотеки: по возможности без тяжёлых (MudBlazor и т.п. — только если реально упрощает). Своя аккуратная CSS.
- Хранилище за интерфейсом (репозиторий/сервис), чтобы можно было сменить SQLite → PostgreSQL.
- Авторизация на этапе localhost не нужна; заложить место под ASP.NET Identity на будущее (когда сервер будет смотреть в сеть).

## 3. Экран (десктоп)

Три зоны слева направо:

### 3.1. Слева — «Роли и цели» (недельный лист Кови)
- Сверху блок **«Затачивание пилы»**: 4 измерения — тело, ум, дух, общение/эмоции; у каждого 0..n целей на неделю.
- Ниже — список **ролей** (пользовательские, редактируемые: переименовать, цвет, порядок, добавить/удалить).
  Стартовые примеры: «Я сама», «Семья», «Работа», «Дом».
- У каждой роли — 1–3 **цели на неделю** («большие камни»). Цель можно перетащить в конкретный день.
- **Цель — шаблон занятий.** У цели «раз в неделю» (1–7) и необязательные время, квадрант, длительность, заметки (окно цели — по клику).
  Перетаскивание цели в день добавляет новое **занятие** (дело-«камень» с её значениями), а не переносит; перенос занятия — перетаскиванием дела.
  Изменение цели расходится по невыполненным занятиям, кроме полей, которые у занятия «свои» (отличаются от цели: метка «своё», кнопка «как у цели»).
  Роли и квадрант у занятий всегда от цели (см. ниже про несколько ролей). Строка цели: прогресс «2/5» справа, дни занятий «Чт · Пт» мелко под названием.
  Цель выполнена, когда отмечено N занятий; галочка у цели отмечает ближайшее занятие (или добавляет выполненное на сегодня).
  **Не больше одного занятия цели в день** (если в окне цели не включено «можно несколько раз в день»): цель, брошенная на день,
  где её занятие уже есть, ничего не создаёт — существующее занятие коротко подсвечивается, подсказка «уже есть в этот день»;
  перенести занятие в такой день тоже нельзя (остаётся на месте); галочка цели не добавляет второе занятие на сегодня
  («сегодня уже отмечено»). Уже существующие дубли не трогаются.
  Удаление цели: выполненные занятия остаются обычными делами, невыполненные — в корзину, мысль из ленты без дня — обратно в ленту.
- **Постоянные цели («каждую неделю»).** В окне цели — переключатель «каждую неделю»: у новых целей измерений пилы включён, у обычных ролей выключен.
  У постоянной цели на каждой следующей неделе сама появляется цель с тем же шаблоном (название, раз в неделю, время, длительность, заметки,
  квадрант, роль) — без занятий, прогресс с нуля; появляется, когда неделю открывают (пропущенные недели заполняются тоже), без дублей.
  Правка шаблона постоянной цели — для этой недели и всех следующих, прошлые недели не меняются. Выключили «каждую неделю» — серия заканчивается
  после этой недели. Удаление постоянной цели — вопрос «Только на этой неделе» (на следующей снова появится) / «С этой недели и дальше»
  (серия заканчивается, прошлые недели остаются) / «Отмена», потом плашка «Вернуть».
  **Дни постоянной цели**: в окне цели строка «Повтор [▾]» — «сам раскладываю» (по умолчанию), «каждый день», «будни», «выходные», «свои дни»;
  под ней 7 круглых переключателей П В С Ч П С В (при «сам раскладываю» скрыты), ручное переключение кружка — «свои дни».
  Если дни выбраны: «раз в неделю» = их числу (поле заблокировано); на каждой новой неделе серии занятия сами встают в эти дни
  (время и длительность — из шаблона). Смена дней — с этой недели и дальше: на этой и уже созданных следующих неделях в выбранные
  дни без занятия добавляется занятие, невыполненные в невыбранные дни — в корзину (плашка «Убрано занятий: N · Вернуть»),
  выполненные не трогаются. Занятие можно вручную перенести на другой день — оно остаётся камнем, дни серии не меняются.
- **Несколько ролей у цели.** В окне цели роли — чипы «● Тело ×» + «+» (можно несколько, хотя бы одна: у последней «×» нет).
  Цель показывается в левой панели под каждой своей ролью — это одна и та же цель с общим прогрессом (отметили занятие — видно во всех ролях);
  в каждой роли у неё своё место в списке (новая роль — в конец). В «камнях» шапки цель считается один раз. Роли занятий = роли цели
  (на записи — точки всех ролей). У постоянной цели роли — часть шаблона: правка — с этой недели и дальше.
  Перетаскивание цели на другую роль — перенос: роль, из-под которой тащили, заменяется новой (остальные роли остаются);
  **с зажатым Shift** — роль добавляется (у призрака подпись «+ роль»). В пределах своей роли — только порядок.
  Удаление роли: цели, у которых она единственная, удаляются (как сейчас); у целей с другими ролями роль просто убирается (и из шаблона серии).
- **У дела — одна цель.** Занятие относится к одной своей цели. Сделать дело занятием цели — перетащить его на середину строки цели
  в левой панели (подсветка «сделать занятием этой цели»; у верхнего/нижнего края строки — новая цель между строками;
  мысль из ленты станет занятием без дня). Было занятием другой цели — переходит к этой (у прежней прогресс уменьшается).
  В окне дела выбора целей нет: роли и квадрант там «от цели».
  «Одно занятие цели в день»: если у цели в этот день другое невыполненное занятие — оно заменяется (в корзину, плашка «Заменено «…» · Вернуть»);
  выполненное — дело не привязывается, «уже есть в этот день». Дни постоянной цели: в день с привязанным делом новое занятие не создаётся.
- Под целями роли — тихая строка **«ещё дела: N ▸»**: дела показанной недели с этой ролью, кроме занятий целей; нет таких — нет строки.
  Клик раскрывает компактный список «Чт · название» (выполненные зачёркнуты), клик по делу — его окно. Раскрытие запоминается (в браузере).

### 3.2. Центр — неделя
- 7 колонок-дней (Пн–Вс), навигация «← неделя →», «Сегодня».
  В шапке — «камней: 2 из 8 · занятий X из Y» (занятия целей недели: отмеченные / всего по «раз в неделю»);
  подсказка при наведении: «камень выполнен, когда отмечены все его занятия».
- **Сетки часов НЕТ** (решение после просмотра прототипа: по духу Кови — гибкость и приоритеты, а не расписание по часам).
  День — это просто список дел в ручном порядке. День растёт вниз вместе со списком, «+ дело» — сразу под последним делом;
  все дни недели одной высоты (по самому длинному), неделя прокручивается вертикально.
- У дела может быть **необязательное время** (реальная встреча: «15:00 Стоматолог») — показывается маленькой меткой-пилюлей на карточке.
  Дела со временем в списке дня автоматически встают по времени; дела без времени — в ручном порядке.
- У дела может быть **необязательная примерная длительность** («~30 мин») — пилюля на карточке; в заголовке дня — сумма «~3 ч».
  Расписания по ней нет — это только оценка нагрузки дня.
- **Окна компактные** (дело, цель, мысль ленты): вместо рядов чипов — поля с выпадающими списками. Роли — чипы выбранных «● Тело ×» + «+»
  (список: точка, название, галочка; закрывается кликом мимо или Esc — окно под ним остаётся); где роль «от цели» — только чипы.
  Одиночный выбор (категория мысли, роль, повтор) — поле «● Книги ▾». Время и длительность — поле «07:30» / «1 ч 30 мин» / «без»,
  по клику — барабан как в будильнике iPhone: часы | минуты (шаг 1; часы времени 0–23, длительности 0–12), колесо, перетаскивание,
  палец, ↑↓, клик по числу — ввод с клавиатуры; «без» сбрасывает. Пустое поле при открытии получает 09:00 / 30 мин.
- Задача: отметка «выполнено», редактирование по клику (название, заметки, роли, время, длительность, квадрант), цвет роли точкой/кружком-чекбоксом,
  **несколько ролей** у дела: в окне — маленькие чипы «● Тело ×» и «+» со списком ролей (множественный выбор); на записи чекбокс цвета первой роли
  (по порядку ролей), при двух ролях и больше — маленькие точки всех ролей под названием. Цель (камень) у дела по-прежнему одна,
  метка «камень», если дело — занятие цели недели, необязательная отметка квадранта I–IV (на карточке не показывается).
- **Перенос на другую неделю.** В окне дела — поле «Дата»: календарь (любая дата) и кнопки «сегодня», «завтра», «через неделю», «без даты»
  («без даты» — обратно в ленту, в свою категорию или в «неразобранное»). Дело встаёт в конец дел дня без времени, время и длительность сохраняются.
  Перенос на другую неделю — плашка «Перенесено на Пн 12 окт · Показать».
  Перетаскиванием: пока тащат дело, по краям недели проступают широкие полупрозрачные зоны «‹ прошлая неделя» / «следующая неделя ›»
  (на всю высоту, в цветах темы; бросить дело у края понедельника/воскресенья можно сквозь них). Задержать над зоной или над стрелкой
  «‹ ›» в шапке ~0,5 с — неделя перелистывается (держишь дальше — листается дальше),
  дело можно бросить в любой день новой недели; Esc или бросок мимо — неделя возвращается. Цели так не листаются — они привязаны к своей неделе.
  Занятие цели («камень») при переносе на другую неделю остаётся камнем: становится занятием той же цели на той неделе (цели её серии),
  а если её там нет — там создаётся эта цель (1 раз в неделю, тот же шаблон, без повтора). У прежней цели прогресс уменьшается.
- «Сегодня» обновляется само: в полночь и когда окно снова активно; если наступила новая неделя, а на экране текущая — переключается на новую.

### 3.3. Справа — лента «Когда-нибудь» (узкая полоса, ~260–300px)
- **Никаких сроков и дат** в ленте. Это склад мыслей: может сделаю на следующей неделе, может через 10 лет, может передумаю.
- **Категории** — ОДИН уровень (без подкатегорий). Категории ленты — НЕ то же самое, что роли Кови (роли = «кто я», категории = «о чём дело»).
- **«Неразобранное»**: мысли можно записывать без категории. Они копятся сверху ленты, над категориями, без заголовка-папки —
  с тихой подписью «неразобранное» и счётчиком; пустое не видно (во время перетаскивания — место, куда бросить, поверх строки
  «+ категория», без сдвига ленты). Перетаскивание из «неразобранного» в категорию и обратно — как между категориями.
  Это не категория (в модели — дело ленты с CategoryId = null), переименовать или удалить его нельзя.
- Вид — **аккордеон**: заголовок категории с серым счётчиком дел; клик раскрывает/сворачивает. Раскрыто может быть **сколько угодно** категорий одновременно; состояние раскрытия запоминается.
- Вся лента — одна прокручиваемая колонка: колесо мыши листает и внутри раскрытых категорий, и по всем категориям подряд.
- Сверху — **поиск** (фильтрует по всем категориям, раскрывая совпадения).
- В конце каждой раскрытой категории — строка «+ добавить»: ввод текста + Enter, без форм. Новое дело — в конец категории (а из «Записать мысль» сверху ленты — наверх).
- Сверху над категориями — «+ категория» (новая встаёт в начало) и «свернуть / развернуть всё»; внизу — тоже «+ категория» (в конец).
- Сверху ленты — быстрое поле «Записать мысль…» + выбор категории: по умолчанию — «неразобранное»; выбранная категория держится до перезагрузки.
- У категории может быть эмодзи-иконка (необязательно).
- Поле «Записать мысль» есть всегда; если категорий ещё нет — под ним подсказка «создайте первую категорию».
- Дело, созданное прямо в плане, категории не имеет, пока лежит в плане. При возврате в ленту: перетаскиванием — туда, куда бросили;
  другим способом (обзор недели, восстановление из корзины, удаление цели или роли) — в исходную категорию, а если её нет — в «неразобранное» (без вопросов).
- Удаление категории: пустая удаляется сразу; непустая — вопрос «Удалить „Название“? В ней N дел» с кнопками
  «Переложить в неразобранное» (дела наверх «неразобранного», в том же порядке) / «Удалить вместе с делами» (дела — в корзину) / «Отмена».
- Порядок дел внутри категории — ручной (drag). Дела можно перетаскивать между категориями.
- Клик по делу ленты — окно редактирования: название, подробное описание (заметки), категория.
- Длинные записи в ленте и в днях — не больше 2 строк, с «…»; в строке не разворачиваются. Полный текст — во всплывающей подсказке
  (навести и задержать ~0,5 с; только если текст обрезан) и в окне по клику.
- Внизу — «+ категория».
- **Корзина**: маленькая серая иконка в самом низу ленты, без яркого счётчика, не отвлекает. Клик — небольшое всплывающее окно со списком удалённого: «вернуть» / «удалить навсегда» (с подтверждением в строке) / «очистить всё». Хранится бессрочно, чистится только вручную.
- **Защита от случайного удаления.** Крестиков удаления в строках ленты и дней нет: удаляют из окна («в корзину») или перетаскиванием записи
  (дело, мысль, цель) на значок корзины — при наведении он подсвечивается. После любого удаления (дело, мысль, цель, роль, категория, очистка корзины)
  внизу на 6 секунд плашка «Удалено «…» · Вернуть»; «Вернуть» отменяет полностью. Устроено так: экран меняется сразу, а на сервер удаление уходит
  через 6 секунд — или раньше, перед любым другим изменением или когда окно уходит в фон (тогда «Вернуть» уже не предлагается).
  Исключение — «удалить навсегда» в корзине: там подтверждение, без плашки.

### 3.4. Привычки — банки со скрепками («Атомные привычки»)

Макет и **все правила подсчёта** — `docs/habits-mockup.html` (блок «правила (для ТЗ)» обязателен).
- **Привычка = постоянная цель «Затачивания пилы».** Любая серия целей с «каждую неделю» в одном из 4 измерений пилы
  (Тело, Ум, Дух, Общение и эмоции) — привычка с банкой; отдельной сущности «копилка» и ручной привязки нет.
  Разовые цели пилы и цели обычных ролей банки не имеют. Создать привычку — добавить постоянную цель в пилу.
- **Скрепка** — выполненное занятие цели этой серии (корзина и шаги не считаются). Всего = стартовое число + скрепки;
  **вычисляется, не хранится**: сняли галочку — скрепка ушла. Полных банок = всего ÷ размер банки (по умолчанию 30), в текущей — остаток.
- **Норма недели — «раз в неделю» цели той недели.** Правка цели (норма, дни, время, роли) «с этой недели и дальше» прошлые недели
  не меняет: они оцениваются по своей тогдашней норме — у привычки одна непрерывная история (серия при правке не делится).
  Неделя без цели (удалили «только на этой неделе», серия закончилась) — без нормы: не засчитана и не пропуск.
- Неделя засчитана, если скрепок ≥ нормы. Текущая неделя «в процессе» и серию не ломает, но как только её норма выполнена — сразу входит
  в серию и снимает паузу (награда мгновенно); месяц — только по окончании. Серия недель 🔥: первый пропуск — ⚠ пауза
  («не пропускай дважды»), второй подряд — обрыв (пауза перед ним показывается пропуском). Недели до первой недели серии не считаются;
  первая неделя без нормы — не пропуск. Месяц — по четвергу недели; засчитан, если в нём серия недель не прервалась; серия месяцев 🌙 — так же.
- **Каникулы** (с — по, все привычки или выбранные): неделя с ≥ 4 днями каникул — не засчитана и не пропуск, серия замирает;
  месяц из одних каникул — каникулы. Скрепки в каникулы идут в общий счёт.
- **Архив.** Сняли «каждую неделю» (или удалили цель «с этой недели и дальше») — привычка уходит в архив экрана 🫙 со всей историей;
  снова включили — история продолжается. Законченные серии без скрепок и с банкой по умолчанию в архиве не показываются.
- Экран «Копилки» — кнопка 🫙 в шапке недели: карточки сгруппированы по 4 измерениям пилы (привычка в нескольких измерениях — один раз,
  в группе первого по порядку ролей, остальные — маленькими чипами на карточке); на карточке — банка, счёт, полка, 🔥/🌙/⚠,
  «эта неделя» точками, 26 недель (в подсказке — норма той недели), 7 месяцев, среднее, месяц, год; «+1 сегодня» и «настроить»
  (стартовое число, размер банки). Внизу — свёрнутый архив; «удалить» — только у привычки из архива: плашка «Удалено … · Вернуть»
  на 6 с, удаление на сервере отложенное. **Удаление привычки не удаляет цель и её дела** — только счёт (стартовое число, размер банки,
  каникулы этой привычки); снова включили «каждую неделю» — привычка вернётся с банкой по умолчанию. Там же «🏖 Каникулы».
- **«+1 сегодня»** — занятие цели этой недели на сегодня, отмеченное: есть невыполненное сегодняшнее — отмечается, иначе новое встаёт в конец
  дня. «Одно занятие в день» — как у галочки цели: сегодня уже отмечено — «сегодня уже отмечено».
- У цели-привычки в левой панели — пилюля «🫙 102 · 🔥13» (пауза — «⚠»), клик — экран на этой привычке. В окне такой цели — строка
  «🫙 привычка: 102 скрепки · 🔥13» (клик — экран 🫙) и настройки банки: стартовое число, размер. В окне дела ничего про привычки нет.
  Отметили занятие привычки — внизу на пару секунд «📎 +1 в «Бег» · 103 · неделя 3 из 3 ✓».
- Логика — `Planner.Core/Habits/HabitStatsCalculator` (чистая функция, unit-тесты на все крайние случаи) и `Services/HabitService`.
  API: `GET /api/habits` (только чтение, вся статистика одним запросом по занятиям), `PUT /api/habits/{id}` (банка),
  `DELETE /api/habits/{id}` (только из архива), `POST /api/habits/{id}/plus-one`, `/api/vacations`. Id привычки — id серии.

**Шаги дела (минимальные, до этапа 4).** Шаг — дело с ParentId (один уровень). В окне дела (план и лента) — список шагов:
добавить (Enter), отметить, переименовать (клик), удалить (×, сразу, без корзины); меняется сразу, без «Сохранить».
В днях, ленте и корзине шагов нет; дело удалили насовсем — шаги вместе с ним. Засчитывание шага в цель и автоотметка дела — этап 4.
API: `GET/POST /api/tasks/{id}/steps`, `PUT /api/steps/{id}`, `PUT /api/steps/{id}/done`, `DELETE /api/steps/{id}`.

## 4. Перетаскивание (ключевая фича)

- Лента → день, лента → цели роли.
- План → обратно в ленту (задача снова без даты, в своей исходной категории).
- Внутри плана: между днями и внутри дня (порядок); на другую неделю — задержать дело над краем недели или стрелкой «‹ ›» в шапке.
- Внутри ленты: переупорядочивание и перенос между категориями.
- Реализация на **pointer events** (не HTML5 DnD — он плохо работает на iOS Safari): мышь — сразу, палец — после долгого нажатия (~300 мс). Призрак карточки, подсветка зоны сброса, автоскролл ленты и недели у краёв.
- Изменения сохраняются на сервер сразу (оптимистичное обновление UI).

## 5. Модель данных

- `Task` — Id, Title, Notes?, CategoryId? (для ленты; у дела ленты null — «неразобранное»), роли (0..n, таблица TaskRoles: TaskId + RoleId), Quadrant? (1–4), цель (0..1, таблица TaskGoals: TaskId + GoalId + Position — всегда 0),
  State: Someday | Planned | Done | Trashed,
  PlannedDate? (DateOnly), StartTime? (TimeOnly — необязательная метка времени, без сетки),
  DurationMinutes? (примерная длительность, 1–1440),
  SortOrder, CreatedAt, CompletedAt?, TrashedAt?, PreviousState (для возврата из корзины).
- `Category` — Id, Name, Emoji?, SortOrder, IsExpanded. Без IsSystem/«Входящих».
- `Role` — Id, Name, Color, SortOrder, SawDimension? (Body | Mind | Spirit | Social — 4 измерения пилы; у обычных ролей null).
- `WeeklyGoal` — Id, роли (1..n, таблица GoalRoles: GoalId + RoleId + SortOrder — место цели в списке этой роли), WeekStart (DateOnly, понедельник), Title, TimesPerWeek (1–7),
  шаблон занятий: StartTime?, Quadrant?, Notes?, DurationMinutes?.
  Занятия — дела, связанные с целью через TaskGoals (много на одну цель; у дела — одна цель); занятия в корзине не считаются.
  «Выполнено» не хранится: цель выполнена, когда занятий в состоянии Done не меньше TimesPerWeek.
  Поле занятия «своё», если его значение отличается от значения цели (отдельных флагов нет).
- `GoalSeries` — «та же цель» на разных неделях: роли (таблица GoalSeriesRoles: SeriesId + RoleId), шаблон (Title, TimesPerWeek, StartTime?, Quadrant?, Notes?, DurationMinutes?),
  IsRecurring («каждую неделю»), FirstWeek, LastWeek? (null — без конца), GeneratedThrough (до какой недели цели уже созданы — поэтому удалённая
  «только на этой неделе» цель сама не возвращается). У `WeeklyGoal` — SeriesId? (уникально вместе с WeekStart). Цели постоянной серии создаются
  лениво — при открытии недели (GET /api/week). Непостоянная серия только связывает цели, между которыми переносили занятия.
- У цели и серии — AllowSeveralPerDay («можно несколько раз в день», по умолчанию false) — часть шаблона.
- У цели и серии — Days? (дни недели, битовая маска Пн = 1 … Вс = 64; null — «сам раскладываю») — часть шаблона; при выбранных днях TimesPerWeek = их числу.
- У серии — банка привычки: JarSize (30), StartCount (0), IsHabitDeleted (привычку удалили из архива; снова «каждую неделю» — вернётся).
  Привычка — не сущность, а постоянная серия с ролью-измерением пилы; архив — серия закончилась (LastWeek задан).
  `Vacation` — Id, From, To, привычки (таблица VacationHabits: VacationId + HabitId — id серии; пусто — все).
  `Task` — ещё ParentId? (шаг дела, один уровень).
- Задача, вынесенная из ленты в план, — это та же сущность (меняется State/PlannedDate), а не копия; при возврате в ленту возвращается в свою категорию
  (и перестаёт быть занятием цели).

## 6. Мобильная раскладка (этап 2, но не ломать заранее)

- Узкий экран: один день (свайп между днями) или неделя списком; роли и цели — отдельной вкладкой.
- Лента — выезжающая шторка сбоку; перетаскивание из шторки в день.

## 7. Этапы

1. **MVP**: каркас решения, БД, API, десктопный экран (роли/цели, неделя из 7 дней-списков, лента с категориями, поиском, корзиной), перетаскивание, сохранение.
2. **Недельный обзор**: в конце недели — экран с невыполненным; по каждому: перенести / вернуть в ленту / удалить; там же выбор «больших камней» на следующую неделю.
3. PWA + мобильная раскладка + проверка на iPhone.
4. Повторяющиеся дела, квадранты I–IV со статистикой за неделю, архив выполненного.
   **Подзадачи**: дело-чеклист; подзадача может засчитываться в свою цель; дело выполнено, когда отмечены все подзадачи
   (пример: «Прогулка в парке» → «10к шагов» (Тело) + «посидеть на лавочке в тишине» (Дух)).
5. (Опционально) доступ с телефона через Tailscale, Docker-образ, Identity.

## 8. Дизайн

Образец — `docs/design-mockup.html` (открыть в браузере; все цвета и стили — в его CSS, брать оттуда). Утверждённый вариант: структура **«в точку»**, палитра **«Лотос»**.
Ощущение — уютный бумажный блокнот (bullet journal), НЕ офисный/табличный.

- **Преобладает зелёный/бирюза, розовый — только акцент** («сегодня», «камень», кнопка «Сегодня»).
- Фон страницы — градиент: лёгкий розовый край «зефир» `#fff5f9` → `#e3f2ec` → `#d3ece4` → `#b9e0d6`.
- Названия дней — бирюзовые (`--b-deep`), розовым только сегодняшний день. Hover у записей — мятный.
- Три зоны — полупрозрачные плавающие панели со скруглением ~22px, без рамок.
  Левая (роли) — самая светлая и прозрачная (едва заметный шалфей + blur); правая (лента) — чуть мятная.
- Дни — «страницы в точку»: фон с точечной сеткой бирюзового оттенка, скругление ~18px.
  Сегодня — заметно, но мягко: подложка цвета акцента (≈20%) и обводка 2px (переменные темы --today-bg / --today-ring;
  проверка в themes-contrast: обводка от 2:1 к обычному дню), бейдж «сегодня» пастельный; выходные — едва заметный бирюзовый оттенок (≈5%). Никаких резких контрастных выделений.
- Записи — строки, НЕ карточки: квадратный чекбокс цвета роли (зона нажатия — вся левая полоса записи, ~30px), текст, пилюли «время» (бирюзовая) и «камень» (розовая). При наведении — лёгкая розовая подложка.
- Шрифты: **Nunito** — основной; **Caveat** (рукописный) — названия дней недели; **Lora** — заголовки панелей и недели.
- Палитра «Лотос»: текст `#3e4d52`, приглушённый `#657579`, бледный `#828f92`, линии `#efe6e7`;
  розовый — **«Зефир»** — самый светлый, чистый и воздушный, без серости и без коралла: `#f9d0e0` / мягкий `#fff5f9` / глубокий `#c4769a` / текстовый `#a5587c`; бирюза `#9fd6c9` / `#e8f6f2` / `#327b6e`.
  (Глубокие и текстовые оттенки подняты до порогов контраста, см. 8.1.)
- Цвета ролей — 18 пастельных оттенков одинаковой светлоты и мягкости, прохладных; не только розовый и зелёный (образец — `docs/role-palette.html`):
  `#9fd3bd` `#6fbfae` `#8ac2c4` `#b9d3b0` `#cfe3a8` `#f3e3a6` `#a9cde8` `#8fb4e3` `#b7c4f0` `#c9b8ec` `#dcb8e6` `#e8c1dc` `#f9d0e0` `#f2b3c6` `#f6c6b8` `#94b4b5` `#b8c2cc` `#c9c1d6`.

### 8.1. Темы оформления

Образец всех тем с переключателем — `docs/themes.html` (все значения — в его CSS, классы `body.th-*`). Тема — это только набор CSS-переменных (+ шрифты и мелкие стилевые правила), разметка одна.

| Ключ | Название | Характер |
|---|---|---|
| lotus | Лотос | по умолчанию: мята + «зефир», в точку |
| peony | Пион | кремовая бумага, эвкалиптовый зелёный, беж; Cormorant Garamond; веточка эвкалипта в ленте |
| dune | Дюна | тауп, какао, песок; Cormorant Garamond; дюны внизу ленты, строже скругления |
| graphite | Графит | строгая сине-серая, Manrope, дни капсом |
| powder | Пудра | строгая светлая: беж + серо-розовый |
| sea | Море | бирюза, голубой, песок |
| lavender | Лаванда | сирень + шалфей |
| platinum | Платина | светлая серая: геометрия с тонкими серебряными линиями, акценты — графит, Manrope во всём тексте |
| obsidian | Обсидиан | тёмная: геометрия, серебряные линии, редкие искры, акценты — серебристо-белый, Manrope во всём тексте, WCAG AA |
| neon | Неон | киберпанк: чёрный, жёлтый + неоново-голубой, срезанные углы, Chakra Petch, свечение |
| android | Андроид | «клиническая» светлая: белый/серый, голубой светодиод, шестигранники, Exo 2 |

- Переключатель — кнопка-палитра в шапке недели, всплывающий список с мини-превью каждой темы.
- Выбор запоминается (сейчас — в браузере; когда появятся аккаунты — в профиле пользователя).
- Шрифты тем — локально в `wwwroot/fonts` (OFL), грузятся только для выбранной темы.
- Декор (веточка, дюны) — только в свободной нижней части ленты, не перекрывает записи.
- Без логотипов, названий и узнаваемых элементов игр — только настроение.
- Цвета ролей общие для всех тем; в тёмных темах (obsidian, neon) проверить читаемость.
- Контраст (сценарий tests/e2e/themes-contrast.mjs): тёмные темы — весь текст WCAG AA; светлые — основной текст AA (4.5:1, крупный 3:1),
  второстепенный («+ цель», «+ дело», «ещё дела», счётчики, выполненные дела, подсказки) — не ниже 3:1. Поднимать ровно до порога, нежность сохранять.
  Переменные: `--soft` — AA, `--faint` — 3:1, `--b-deep` — AA, `--a-deep` — 3:1 (крупное и значки), `--a-ink` — мелкий розовый текст, AA.

## 9. Правила работы

- git с первого шага, небольшие осмысленные коммиты.
- Перед каждым «готово» — `dotnet build` без ошибок и `dotnet test` зелёный.
- Проверять UI в браузере (`dotnet run --project Planner.Server`), особенно перетаскивание.
- Не добавлять платные сервисы и внешние облачные зависимости.
- Комментарии и UI — на русском; идентификаторы в коде — на английском.
- README с инструкцией: как запустить, где лежит файл БД, как сделать бэкап.
