# CoveyPlanner — ТЗ и правила проекта

Личный планировщик по мотивам недельного листа Стивена Кови («7 навыков высокоэффективных людей», глава 3 «Главное — вперёд»)
плюс лента дел «когда-нибудь», из которой задачи перетаскиваются в план.

Владелец — Анна, C#-разработчик. Код должен быть понятным, идиоматичным C#, чтобы его было легко дорабатывать руками.

---

## 1. Цели и ограничения

- Сейчас: пользоваться с компьютера через браузер (сервер крутится локально).
- Потом: iPhone (PWA, «На экран Домой») и веб. Нативное iOS-приложение НЕ делаем.
- Ничего платного. Никаких сторонних облаков/BaaS (Supabase, Firebase и т.п.) — приложение независимое, данные у владельца.
- Путь роста: localhost → телефон через Tailscale/ZeroTier к домашнему ПК → (опционально) VPS/Docker. Код при этом не меняется.

## 2. Стек

- .NET 10 (LTS).
- `Planner.Server` — ASP.NET Core Web API (minimal API или контроллеры), EF Core + SQLite (один файл БД), миграции EF.
  Сервер также хостит клиент (Blazor WASM hosted).
- `Planner.Client` — Blazor WebAssembly, PWA (manifest + service worker), интерфейс на Razor/C#. JS — только точечно через JS interop, если без него никак.
- `Planner.Shared` — DTO и контракты API.
- `Planner.Core` — доменная модель и логика (без зависимостей от ASP.NET / EF).
- `Planner.Tests` — xUnit, тесты на доменную логику и API (WebApplicationFactory).
- UI-библиотеки: по возможности без тяжёлых (MudBlazor и т.п. — только если реально упрощает). Своя аккуратная CSS.
- Хранилище за интерфейсом (репозиторий/сервис), чтобы можно было сменить SQLite → PostgreSQL.
- Авторизация на этапе localhost не нужна; заложить место под ASP.NET Identity на будущее (когда сервер будет смотреть в сеть).

## 3. Экран (десктоп)

Три зоны слева направо:

### 3.1. Слева — «Роли и цели» (недельный лист Кови)
- Сверху блок **«Затачивание пилы»**: 4 измерения — тело, ум, дух, общение/эмоции; у каждого 0..n целей на неделю.
- Ниже — список **ролей** (пользовательские, редактируемые: переименовать, цвет, порядок, добавить/удалить).
  Стартовые примеры: «Я сама», «Семья», «Работа», «Дом».
- У каждой роли — 1–3 **цели на неделю** («большие камни»). Цель можно перетащить в конкретный день.
- **Цель — шаблон занятий.** У цели «раз в неделю» (1–7) и необязательные время, квадрант, длительность, заметки (окно цели — по клику).
  Перетаскивание цели в день добавляет новое **занятие** (дело-«камень» с её значениями), а не переносит; перенос занятия — перетаскиванием дела.
  Изменение цели расходится по невыполненным занятиям, кроме полей, которые у занятия «свои» (отличаются от цели: метка «своё», кнопка «как у цели»).
  Роль и квадрант у занятий всегда от цели. Строка цели: прогресс «2/5» справа, дни занятий «Чт · Пт» мелко под названием.
  Цель выполнена, когда отмечено N занятий; галочка у цели отмечает ближайшее занятие (или добавляет выполненное на сегодня).
  Удаление цели: выполненные занятия остаются обычными делами, невыполненные — в корзину, мысль из ленты без дня — обратно в ленту.

### 3.2. Центр — неделя
- 7 колонок-дней (Пн–Вс), навигация «← неделя →», «Сегодня».
- **Сетки часов НЕТ** (решение после просмотра прототипа: по духу Кови — гибкость и приоритеты, а не расписание по часам).
  День — это просто список дел в ручном порядке. День растёт вниз вместе со списком, «+ дело» — сразу под последним делом;
  все дни недели одной высоты (по самому длинному), неделя прокручивается вертикально.
- У дела может быть **необязательное время** (реальная встреча: «15:00 Стоматолог») — показывается маленькой меткой-пилюлей на карточке.
  Дела со временем в списке дня автоматически встают по времени; дела без времени — в ручном порядке.
- У дела может быть **необязательная примерная длительность** («~30 мин») — пилюля на карточке; в заголовке дня — сумма «~3 ч».
  Расписания по ней нет — это только оценка нагрузки дня.
- Задача: отметка «выполнено», редактирование по клику (название, заметки, роль, время, длительность, квадрант), цвет роли точкой/кружком-чекбоксом,
  метка «камень», если дело — занятие цели недели, необязательная отметка квадранта I–IV (на карточке не показывается).
- «Сегодня» обновляется само: в полночь и когда окно снова активно; если наступила новая неделя, а на экране текущая — переключается на новую.

### 3.3. Справа — лента «Когда-нибудь» (узкая полоса, ~260–300px)
- **Никаких сроков и дат** в ленте. Это склад мыслей: может сделаю на следующей неделе, может через 10 лет, может передумаю.
- **Категории** — ОДИН уровень (без подкатегорий). Категории ленты — НЕ то же самое, что роли Кови (роли = «кто я», категории = «о чём дело»).
- **«Неразобранное»**: мысли можно записывать без категории. Они копятся сверху ленты, над категориями, без заголовка-папки —
  с тихой подписью «неразобранное» и счётчиком; пустое не видно (во время перетаскивания — место, куда бросить, поверх строки
  «+ категория», без сдвига ленты). Перетаскивание из «неразобранного» в категорию и обратно — как между категориями.
  Это не категория (в модели — дело ленты с CategoryId = null), переименовать или удалить его нельзя.
- Вид — **аккордеон**: заголовок категории с серым счётчиком дел; клик раскрывает/сворачивает. Раскрыто может быть **сколько угодно** категорий одновременно; состояние раскрытия запоминается.
- Вся лента — одна прокручиваемая колонка: колесо мыши листает и внутри раскрытых категорий, и по всем категориям подряд.
- Сверху — **поиск** (фильтрует по всем категориям, раскрывая совпадения).
- В конце каждой раскрытой категории — строка «+ добавить»: ввод текста + Enter, без форм. Новое дело — в конец категории (а из «Записать мысль» сверху ленты — наверх).
- Сверху над категориями — «+ категория» (новая встаёт в начало) и «свернуть / развернуть всё»; внизу — тоже «+ категория» (в конец).
- Сверху ленты — быстрое поле «Записать мысль…» + выбор категории: по умолчанию — «неразобранное»; выбранная категория держится до перезагрузки.
- У категории может быть эмодзи-иконка (необязательно).
- Поле «Записать мысль» есть всегда; если категорий ещё нет — под ним подсказка «создайте первую категорию».
- Дело, созданное прямо в плане, категории не имеет, пока лежит в плане. При возврате в ленту: перетаскиванием — туда, куда бросили;
  другим способом (обзор недели, восстановление из корзины, удаление цели или роли) — в исходную категорию, а если её нет — в «неразобранное» (без вопросов).
- Удаление категории: пустая удаляется сразу; непустая — вопрос «Удалить „Название“? В ней N дел» с кнопками
  «Переложить в неразобранное» (дела наверх «неразобранного», в том же порядке) / «Удалить вместе с делами» (дела — в корзину) / «Отмена».
- Порядок дел внутри категории — ручной (drag). Дела можно перетаскивать между категориями.
- Клик по делу ленты — окно редактирования: название, подробное описание (заметки), категория.
- Длинные записи в ленте и в днях — не больше 2 строк, с «…»; разворачиваются кликом по «…» или по стрелке справа.
- Внизу — «+ категория».
- **Корзина**: маленькая серая иконка в самом низу ленты, без яркого счётчика, не отвлекает. Клик — небольшое всплывающее окно со списком удалённого: «вернуть» / «удалить навсегда» / «очистить всё». Хранится бессрочно, чистится только вручную.

## 4. Перетаскивание (ключевая фича)

- Лента → день, лента → цели роли.
- План → обратно в ленту (задача снова без даты, в своей исходной категории).
- Внутри плана: между днями и внутри дня (порядок).
- Внутри ленты: переупорядочивание и перенос между категориями.
- Реализация на **pointer events** (не HTML5 DnD — он плохо работает на iOS Safari): мышь — сразу, палец — после долгого нажатия (~300 мс). Призрак карточки, подсветка зоны сброса, автоскролл ленты и недели у краёв.
- Изменения сохраняются на сервер сразу (оптимистичное обновление UI).

## 5. Модель данных

- `Task` — Id, Title, Notes?, CategoryId? (для ленты; у дела ленты null — «неразобранное»), RoleId?, Quadrant? (1–4), GoalId? (дело — занятие цели),
  State: Someday | Planned | Done | Trashed,
  PlannedDate? (DateOnly), StartTime? (TimeOnly — необязательная метка времени, без сетки),
  DurationMinutes? (примерная длительность, 1–1440),
  SortOrder, CreatedAt, CompletedAt?, TrashedAt?, PreviousState (для возврата из корзины).
- `Category` — Id, Name, Emoji?, SortOrder, IsExpanded. Без IsSystem/«Входящих».
- `Role` — Id, Name, Color, SortOrder, SawDimension? (Body | Mind | Spirit | Social — 4 измерения пилы; у обычных ролей null).
- `WeeklyGoal` — Id, RoleId, WeekStart (DateOnly, понедельник), Title, TimesPerWeek (1–7), SortOrder,
  шаблон занятий: StartTime?, Quadrant?, Notes?, DurationMinutes?.
  Занятия — дела с `Task.GoalId` (много на одну цель); занятия в корзине не считаются.
  «Выполнено» не хранится: цель выполнена, когда занятий в состоянии Done не меньше TimesPerWeek.
  Поле занятия «своё», если его значение отличается от значения цели (отдельных флагов нет).
- Задача, вынесенная из ленты в план, — это та же сущность (меняется State/PlannedDate), а не копия; при возврате в ленту возвращается в свою категорию
  (и перестаёт быть занятием цели).

## 6. Мобильная раскладка (этап 2, но не ломать заранее)

- Узкий экран: один день (свайп между днями) или неделя списком; роли и цели — отдельной вкладкой.
- Лента — выезжающая шторка сбоку; перетаскивание из шторки в день.

## 7. Этапы

1. **MVP**: каркас решения, БД, API, десктопный экран (роли/цели, неделя из 7 дней-списков, лента с категориями, поиском, корзиной), перетаскивание, сохранение.
2. **Недельный обзор**: в конце недели — экран с невыполненным; по каждому: перенести / вернуть в ленту / удалить; там же выбор «больших камней» на следующую неделю.
3. PWA + мобильная раскладка + проверка на iPhone.
4. Повторяющиеся дела, квадранты I–IV со статистикой за неделю, архив выполненного.
5. (Опционально) доступ с телефона через Tailscale, Docker-образ, Identity.

## 8. Дизайн

Образец — `docs/design-mockup.html` (открыть в браузере; все цвета и стили — в его CSS, брать оттуда). Утверждённый вариант: структура **«в точку»**, палитра **«Лотос»**.
Ощущение — уютный бумажный блокнот (bullet journal), НЕ офисный/табличный.

- **Преобладает зелёный/бирюза, розовый — только акцент** («сегодня», «камень», кнопка «Сегодня»).
- Фон страницы — градиент: лёгкий розовый край «зефир» `#fff5f9` → `#e3f2ec` → `#d3ece4` → `#b9e0d6`.
- Названия дней — бирюзовые (`--b-deep`), розовым только сегодняшний день. Hover у записей — мятный.
- Три зоны — полупрозрачные плавающие панели со скруглением ~22px, без рамок.
  Левая (роли) — самая светлая и прозрачная (едва заметный шалфей + blur); правая (лента) — чуть мятная.
- Дни — «страницы в точку»: фон с точечной сеткой бирюзового оттенка, скругление ~18px.
  Сегодня — заметно, но мягко: подложка цвета акцента (≈20%) и обводка 2px (переменные темы --today-bg / --today-ring;
  проверка в themes-contrast: обводка от 2:1 к обычному дню), бейдж «сегодня» пастельный; выходные — едва заметный бирюзовый оттенок (≈5%). Никаких резких контрастных выделений.
- Записи — строки, НЕ карточки: квадратный чекбокс цвета роли (зона нажатия — вся левая полоса записи, ~30px), текст, пилюли «время» (бирюзовая) и «камень» (розовая). При наведении — лёгкая розовая подложка.
- Шрифты: **Nunito** — основной; **Caveat** (рукописный) — названия дней недели; **Lora** — заголовки панелей и недели.
- Палитра «Лотос»: текст `#3e4d52`, приглушённый `#657579`, бледный `#828f92`, линии `#efe6e7`;
  розовый — **«Зефир»** — самый светлый, чистый и воздушный, без серости и без коралла: `#f9d0e0` / мягкий `#fff5f9` / глубокий `#c4769a` / текстовый `#a5587c`; бирюза `#9fd6c9` / `#e8f6f2` / `#327b6e`.
  (Глубокие и текстовые оттенки подняты до порогов контраста, см. 8.1.)
- Цвета ролей — 18 пастельных оттенков одинаковой светлоты и мягкости, прохладных; не только розовый и зелёный (образец — `docs/role-palette.html`):
  `#9fd3bd` `#6fbfae` `#8ac2c4` `#b9d3b0` `#cfe3a8` `#f3e3a6` `#a9cde8` `#8fb4e3` `#b7c4f0` `#c9b8ec` `#dcb8e6` `#e8c1dc` `#f9d0e0` `#f2b3c6` `#f6c6b8` `#94b4b5` `#b8c2cc` `#c9c1d6`.
  Стартовые: Тело `#9fd3bd`, Ум `#a9cde8`, Дух `#c9b8ec`, Общение `#f9d0e0`, Я сама `#dcb8e6`, Семья `#b9d3b0`, Работа `#8fb4e3`, Дом `#f3e3a6`.
- Иконки категорий — эмодзи. Минимум линий, больше воздуха.

### 8.1. Темы оформления

Образец всех тем с переключателем — `docs/themes.html` (все значения — в его CSS, классы `body.th-*`). Тема — это только набор CSS-переменных (+ шрифты и мелкие стилевые правила), разметка одна.

| Ключ | Название | Характер |
|---|---|---|
| lotus | Лотос | по умолчанию: мята + «зефир», в точку |
| peony | Пион | кремовая бумага, эвкалиптовый зелёный, беж; Cormorant Garamond; веточка эвкалипта в ленте |
| dune | Дюна | тауп, какао, песок; Cormorant Garamond; дюны внизу ленты, строже скругления |
| graphite | Графит | строгая сине-серая, Manrope, дни капсом |
| powder | Пудра | строгая светлая: беж + серо-розовый |
| sea | Море | бирюза, голубой, песок |
| lavender | Лаванда | сирень + шалфей |
| platinum | Платина | светлая серая: геометрия с тонкими серебряными линиями, акценты — графит, Manrope во всём тексте |
| obsidian | Обсидиан | тёмная: геометрия, серебряные линии, редкие искры, акценты — серебристо-белый, Manrope во всём тексте, WCAG AA |
| neon | Неон | киберпанк: чёрный, жёлтый + неоново-голубой, срезанные углы, Chakra Petch, свечение |
| android | Андроид | «клиническая» светлая: белый/серый, голубой светодиод, шестигранники, Exo 2 |

- Переключатель — кнопка-палитра в шапке недели, всплывающий список с мини-превью каждой темы.
- Выбор запоминается (сейчас — в браузере; когда появятся аккаунты — в профиле пользователя).
- Шрифты тем — локально в `wwwroot/fonts` (OFL), грузятся только для выбранной темы.
- Декор (веточка, дюны) — только в свободной нижней части ленты, не перекрывает записи.
- Без логотипов, названий и узнаваемых элементов игр — только настроение.
- Цвета ролей общие для всех тем; в тёмных темах (obsidian, neon) проверить читаемость.
- Контраст (сценарий tests/e2e/themes-contrast.mjs): тёмные темы — весь текст WCAG AA; светлые — основной текст AA (4.5:1, крупный 3:1),
  второстепенный («+ цель», «+ дело», счётчики, выполненные дела, подсказки) — не ниже 3:1. Поднимать ровно до порога, нежность сохранять.
  Переменные: `--soft` — AA, `--faint` — 3:1, `--b-deep` — AA, `--a-deep` — 3:1 (крупное и значки), `--a-ink` — мелкий розовый текст, AA.

## 9. Правила работы

- git с первого шага, небольшие осмысленные коммиты.
- Перед каждым «готово» — `dotnet build` без ошибок и `dotnet test` зелёный.
- Проверять UI в браузере (`dotnet run --project Planner.Server`), особенно перетаскивание.
- Не добавлять платные сервисы и внешние облачные зависимости.
- Комментарии и UI — на русском; идентификаторы в коде — на английском.
- README с инструкцией: как запустить, где лежит файл БД, как сделать бэкап.
